# REQ-PARITY-NIGHTLY: Implementation plan (Phase 2)

Input: [`2026-10-23-req-nightly-parity-tests.md`](2026-10-23-req-nightly-parity-tests.md). Origin: master plan row `REQ-PARITY-NIGHTLY`. Verified against branch `feat/nightly-parity-tests` (base `3dba661a`).

## 1. Inputs and defaults taken

Owner decisions: sibling `.github/workflows/parity-nightly.yml` (cron `0 2 * * *` + `workflow_dispatch`); SQLite first; PostgreSQL/SQL Server as a separate nightly job; green-to-red fails the workflow; REST/OData and MCP cells `Pending` (cheap REST no-500 included); no auto issue creation; function list source decided here (D-12).

Code facts this plan relies on:
1. SQLite is a supported in-process data source (`Gateway:DataSources:Connections:<name>:Provider=Sqlite`, see `EndToEndSqliteTests`, `TypedAggregationEndToEndTests`). All blocks run in-process on SQLite; no container is needed for the default job. Local verification is possible.
2. Test auth: `Gateway:Authentication:EnableTestAuthHandler=true`, build with `-p:AutherisIncludeTestAuth=true`, headers `X-Test-User-Sid`, `X-Test-Roles`, `X-Test-Tenant`.
3. WebSQL: `POST /api/v1/sql` body `{ "sql": ... }`; 200 body has `columns`, rows, `rowCount`; errors are `{ error, message[, code] }` (`BadRequest`, `NotImplemented` 501, `TooManyRequests`/`TOO_MANY_REQUESTS`, `InternalServerError` 500). GraphQL: `POST /graphql`, typed aggregation field `<source>_<schema>_<table>_aggregate(groupBy, aggregates: [{fn, alias}], where, orderBy)`, enabled by default; errors in `errors[].extensions.code` (sanitizer emits `INTERNAL_SERVER_ERROR` for unexpected faults). REST: `GET /api/v1/data/{domain}/{schema}/{table}`. MCP: `/mcp`, codes in `McpErrorCodes`.
4. xunit is 2.9.3 (no `Assert.Skip`); test projects pin versions per csproj (no central package management). `DuckDB.NET.Data.Full 1.5.6` is already referenced by `Autheris.Application` (approved), so DuckDB is reachable transitively without a new package. `Testcontainers.PostgreSql`/`MsSql 4.16.0` are approved (Integration csproj).
5. Advertised SQL functions: `TrinoSqlEngine.SqlFunctionAllowlists.Sqlite` / `GetDefault(TargetSqlDialect)` (public).
6. `Autheris.Tests.SqlCompilerGate/Parity/*` is an unrelated compiler-parity folder; no name clash because the new project uses namespace `Autheris.Tests.Parity`.

D-3 Defense-in-depth filters. Append `&Category!=Parity` to the solution-wide `dotnet test` filters in `ci.yml` (unit step, line 44), `release.yml` (line 49), `docker-publish.yml` (line 61). `integration-shard-filter.py`: `BASE_FILTER = "Category!=Spark&Category!=Parity"`. No other filter changes.

D-4 Isolation guard in `tests/Autheris.Tests.Architecture/ParityIsolationArchitectureTests.cs` (source/text scan from repo root found via `Autheris.sln`, like `ReleaseBuildExcludesTestAuthTests.FindRepoRoot`). Tests:
`ParityIsolation_ProjectIsNotInAnySolution` (no `*.sln`/`*.slnf` in repo root mentions `Autheris.Tests.Parity`);
`ParityIsolation_OnlyParityWorkflowTargetsParityProject` (no workflow except `parity-nightly.yml` contains `Autheris.Tests.Parity`);
`ParityIsolation_SolutionWideTestRunsExcludeParity` (every `dotnet test Autheris.sln` line in `.github/workflows/*.yml` has `Category!=Parity`);
`ParityIsolation_ShardBaseFilterExcludesParity` (regex on `BASE_FILTER` line);
`ParityIsolation_NightlyWorkflowHasNoPullRequestOrPushTrigger` and `..._SetsParityRunEnv`;
`ParityIsolation_NoOtherProjectUsesParityCategory` (no `"Category", "Parity"` under `tests/` outside the Parity project);
`ParityIsolation_EveryParityTestClassDerivesFromBase` (regex scan of `tests/Autheris.Tests.Parity/**/*Tests.cs`);
`ParityIsolation_KnownGapIdsHaveDrafts` (every `PARITY-GAP-\d{3}` in Parity sources has a `### PARITY-GAP-NNN` heading in section 5 of this plan; no duplicate ids). Each test gets a negative self-check on an in-memory sample string (tests the scanner, not only the repo).

D-5 KnownGap strict xfail (xunit v2). `[ParityFact]`/`[ParityTheory]` with `XunitTestCaseDiscoverer` producing `ParityTestCase : XunitTestCase` / `ParityTheoryTestCase : XunitTheoryTestCase`; `RunAsync` wraps the message bus in `KnownGapMessageBus`, which rewrites `ITestFailed` caused by `KnownGapObservedException` into `TestSkipped("PARITY-GAP-NNN: <reason>")` and `PendingCellException` into `TestSkipped("PENDING: <channel>/<capability>")`. Test bodies use `await KnownGap.RunAsync(cell.GapId, body)`: gap null => run normally; gap set and body throws => `KnownGapObservedException`; gap set and body passes => `Assert.Fail("PARITY-GAP-NNN is fixed: remove the KnownGap")`. Method-level `[KnownGap("PARITY-GAP-NNN","reason")]` is read by the same runner. Unit tests (pure, no host): `KnownGap_FailingBodyIsReportedAsSkipped`, `KnownGap_PassingBodyFails`, `KnownGap_NullIdRunsNormally`, `KnownGap_IdFormatValidated`.

D-6 Results file and gap report. Every cell writes one JSON line to `$AUTHERIS_PARITY_REPORT_DIR/parity-results.jsonl` (default `TestResults/parity`, file appended under a static lock): `{ cellId, block, channel, capability, dialect, outcome: pass|fail|gap|pending, gapId, seed }`. `cellId` is stable (`<block>.<channel>.<capability>.<caseId>`). `.github/scripts/parity-report.py <jsonl> <baseline> <out.md>` renders `known-gaps.md` (table: gap id, channel, capability, cell count, draft heading) plus pass/fail/gap/pending counts, appends to `$GITHUB_STEP_SUMMARY`, and exits 1 if a cell listed `pass` in `tests/Autheris.Tests.Parity/parity-baseline.json` is now `fail` or `gap` (green-to-red). `--update-baseline` rewrites the baseline (developer-run, committed). Cells absent from the baseline never fail the report. Script self-test: `python3 .github/scripts/parity-report.py --self-test` (run in WP1 locally).

D-7 Host fixture. `ParityHostFixture : IAsyncLifetime` (collection fixture, one host per run): temp dir, SQLite data file seeded by `ParitySeed.Create(path)`, `WebApplicationFactory<Program>.WithWebHostBuilder` with the settings of `TypedAggregationEndToEndTests` (test auth, GovernanceDb Sqlite file, `danger_bypass_consent_checks`, Rebac off, PreAuthIpRateLimit 100000, WebSql enabled + `DefaultDataSourceName=default`, AllowDml false, OpenSchema true) and catalog registration via `ITableMetadataRepository.UpsertTableMetadataAsync` for `parity_sales` and `parity_regions`. Second SQLite source `second` (same schema, 4 rows) for federation scenarios. `HttpClient.Timeout = 30 s`; a timeout is a cell failure (no retry, M-5).

D-8 Channels. `IParityChannel { string Name; Task<ChannelResult> ExecuteAsync(ParityQuery q, CancellationToken ct); }`, `ChannelResult(int Status, string? Code, IReadOnlyList<IReadOnlyDictionary<string, object?>> Rows, string RawBody)`. `ParityQuery` is a logical query (table, aggregates, groupBy incl. date part, filter tree, order, page, parameters) rendered per channel: `WebSqlChannel` renders SQL text (`POST /api/v1/sql`), `GraphQlChannel` renders the typed `_aggregate` or list field (`POST /graphql`), `RestChannel` (WP2) renders `GET /api/v1/data/default/main/parity_sales` query string, `McpChannel` returns `Pending`. A capability a renderer cannot express returns `ChannelResult.NotExpressible` and the cell must be in the matrix as `Unsupported` or `Pending`. Code extraction: WebSQL `code ?? error`; GraphQL first `errors[].extensions.code`; REST problem `code ?? title`.

D-9 Invariant C. `ParityAssert.NoServerError(ChannelResult r)` fails on: status >= 500 except 501 with code `NotImplemented` (treated as `Unsupported`); code `INTERNAL_SERVER_ERROR`/`InternalServerError`; GraphQL `errors` without `extensions.code`; body matching stack-trace regex (`\bat [A-Z][\w.]+\(`, `Exception:`); 4xx with empty code or a code not in `ParityErrorCodes.All` (union of public const strings by reflection over `ApiErrorCodes`, `AggregationErrorCodes`, `GovernedSqlErrorCodes`, `McpErrorCodes`, `VirtualFilterErrorCodes`, plus the WebSQL tokens `BadRequest`, `Forbidden`, `Unauthorized`, `NotImplemented`, `TooManyRequests` and GraphQL validation codes). Tests: `NoServerError_FailsOn500`, `NoServerError_FailsOnInternalServerErrorCode`, `NoServerError_FailsOnStackTrace`, `NoServerError_FailsOnUnknownCode`, `NoServerError_AcceptsStable4xx` (fake results), `NoServerError_DetectsInjectedThrowingChannel` (host with a decorated throwing `IQueryExecutor`-level stub registered via `ConfigureTestServices`; asserts the invariant flags it), and the generated sweep `Invariant_NoServerError(channel, caseId)` over D and (later) B/F inputs.

D-10 Boundary catalogue D. `BoundaryValues` static, ordered, each entry `BoundaryValue(string Id, ParityType Type, object? Value, Expectation Expected)` with `Expectation = Ok | Rejected(code)`; ids like `str.empty`, `str.quote`, `str.emoji`, `str.len64k`, `int.max`, `dec.nan_string`, `date.leap_2024_02_29`, `date.invalid_2100_02_29`, `date.dst_2024_03_31`, `tz.invalid`, `page.size_max_plus_1`, `in.empty`, `in.1000`. Applied by `BoundaryCases.For(channel)` to every filter operand, sort key, paging parameter and declared-query parameter column of the seed. Tests: `Boundary_IdsUniqueAndOrdered`, `Boundary_EveryValueHasDecidedExpectation`, `Boundary_Case(channel, valueId, slot)` (asserts the expectation, and C). Case budget: <= 600 cells per channel.

D-11 Seed dataset (`ParitySeed`, SQLite, hand-computed expectations in `ParityExpected`).
`parity_regions(id INTEGER PRIMARY KEY, name TEXT NOT NULL, tz TEXT NOT NULL)`: 1 North/Europe/Berlin, 2 South/UTC, 3 Empty/UTC.
`parity_sales(id INTEGER PRIMARY KEY, region_id INTEGER NULL, region TEXT NULL, product TEXT NOT NULL, qty INTEGER NULL, amount NUMERIC(12,2) NULL, sale_date DATE NOT NULL, sold_at TIMESTAMP NOT NULL, is_return BOOLEAN NULL, note TEXT NULL)`, 18 rows: years 2023/2024/2025; leap day `2024-02-29`; `2024-03-31T00:30:00Z` (Berlin DST day); `2024-12-31T23:30:00Z` (Berlin local 2025-01-01); duplicate rows (same region/product/amount); region `Empty` with all `amount`/`qty` NULL (sum => null); a NULL `region`; notes with `%`, `_`, `'`, `\`, emoji and SQL keyword `SELECT`. Dates as ISO text, timestamps as ISO-8601 UTC text, booleans 0/1. Catalog column types: integer, varchar, decimal, date, timestamp, boolean. `ParityExpected` holds literal expected values per capability (not computed by SQL); `ParitySeed_ExpectedValuesMatchRows` recomputes them in C# LINQ from the row literals.

D-12 Function list for F. Source: `SqlFunctionAllowlists.Sqlite`. `FunctionSignatures` table (name => arity + argument `ParityType`s) in the Parity project; `Spec_EveryAllowlistedFunctionHasSignature` fails when the allowlist gains a function without a row, so new functions force a case; `Spec_Function(name)` calls each once via WebSQL with type-correct seed columns and asserts success or a stable 4xx. GraphQL: `Spec_Field(field, arg)` from `POST /graphql` introspection (`__schema.queryType.fields{name args{name type{kind name ofType{kind name}}}}`), type-driven argument synthesis, then each D value.

D-13 Matrix A. `ParityMatrix.Cells`: key `(Capability, Channel)` => `Supported(ExpectedSpec)` | `Unsupported(code)` | `Pending` | with optional `GapId`. Capabilities as PRD 6.A.1. Channels WebSql, GraphQl, Rest, Mcp; Rest/Mcp = `Pending` except Rest cells covered by the WP2 invariant. Tests: `Matrix_IsComplete` (product == keys), `Matrix_UnsupportedHasCode`, `Matrix_Cell(capability, channel)` (Supported => rows equal `ParityExpected`, order-insensitive unless ordered, decimal tolerance 1e-9 for avg; Unsupported => 4xx with that code and English message naming the capability).

D-14 Pairwise B. `PairwiseGenerator` (in-repo greedy IPOG, `System.Random(seed)` only for tie-breaks), default seed `20261023`, override `AUTHERIS_PARITY_SEED`; seed printed in test output and in every JSONL line. Factors: aggregate {count, count distinct, sum, avg, min, max} x grouping {none, column, year, month, day, expression} x filter {none, empty, eq, range, like, is null, in-list, in-empty, param} x type {int, decimal, string, date, timestamp, bool} x dialect {sqlite; postgres, sqlserver in the container job}. `PairwiseConstraints` maps invalid combos to `Rejected(code)` (sum/avg on string/bool/date). Oracle: type-driven expected-spec rules evaluated by `ParityOracle` in C# over the seed literals. Tests: `Pairwise_SameSeedSameCases`, `Pairwise_CoversEveryPair`, `Pairwise_CaseCountWithinBudget` (<= 400), `Pairwise_Case(channel, caseId)`.

D-15 Dialect job. `ParityDialectHostFixture` starts PostgreSQL/SQL Server via Testcontainers (versions as Integration), seeds the same rows with dialect DDL, registers them as sources `pg`/`mssql`. Classes carry `[Trait("Dialect","Container")]`; the SQLite job filters `Dialect!=Container`. Not verifiable locally (no containers); the developer runs only compile and the pure generator tests locally.

D-16 Differential E. `SqliteReference.Execute(sql)` runs the same logical query rendered as plain SQLite SQL directly on the seed file (Microsoft.Data.Sqlite, transitive). `ResultComparer` (order-insensitive unless ORDER BY, NULL-aware, decimal tolerance). `DifferentialAllowList` entries need a reason and a gap id or `documented:`; `Differential_AllowListEntriesHaveReason`. TLP invariant for container dialects: `COUNT(*) == COUNT(p) + COUNT(NOT p) + COUNT(p IS NULL)` via WebSQL. Negative test: `Differential_DetectsWrongCompilerStub` (decorated executor that drops the WHERE). DuckDB reference is WP5b, optional, no new package.

D-17 Robin suite G. `RobinScenarios.cs`, one `[ParityFact]` per scenario `Robin_<issue>_<slug>` (e.g. `Robin_280_AggregationWhereEqualsValue`, `Robin_128_InListParameter1000`), each asserting the correct result against `ParityExpected` on the issue's channel plus sibling channels via `[ParityTheory]` over channels. WP3 implements PRD section 8 items 1, 3-16, 19-28 (26 cases); item 2 moves to the dialect job (WP4); items 17 (columnless catalog) and 18 (HMAC pseudonymization) need host variants and are registered `Pending`. Checklist line "new rgruebel issue => add Robin case" goes into `.github/pull_request_template.md` (create if absent).

D-18 Workflow `.github/workflows/parity-nightly.yml`. Triggers `schedule: cron '0 2 * * *'` and `workflow_dispatch` (inputs `filter`, `seed`, strings, default empty). `permissions: {}`; job `contents: read`; no secrets; checkout/setup-dotnet/upload-artifact pinned to the SHAs already used in `sql-compiler-gate-nightly.yml`/`ci.yml`; `persist-credentials: false`. Inputs are passed via `env:` only (never `${{ inputs.* }}` inside `run:`) and validated in bash (`filter` must match `^[A-Za-z0-9_.~=!&|()]*$`, `seed` `^[0-9]{0,10}$`, else exit 1). Job `parity-sqlite` (timeout 45 min): `dotnet restore tests/Autheris.Tests.Parity --locked-mode`; `dotnet test tests/Autheris.Tests.Parity -c Release --no-restore -p:AutherisIncludeTestAuth=true --filter "Category=Parity&Dialect!=Container<&filter>" --logger trx` with `AUTHERIS_PARITY_RUN=1`, `AUTHERIS_PARITY_SEED`, `AUTHERIS_PARITY_REPORT_DIR`; `if: always()` report step (D-6) and artifact upload (trx, jsonl, known-gaps.md). Job `parity-dialects` (WP4, same shape, filter `Dialect=Container`, timeout 60 min). Wall time target <= 30 min for `parity-sqlite`.

## 5. Gap drafts (PARITY-GAP-NNN, to become GitHub issues)

Candidates from code reading; each is confirmed (or deleted) by the first run of the WP that covers it. Only confirmed ids may be used in `KnownGap`.

### PARITY-GAP-001
WebSQL 4xx bodies carry a generic `error` token (`BadRequest`) and generic message without a stable fine-grained `code` (e.g. unknown column vs unsupported function vs invalid parameter). Channel WebSQL, all capabilities. Expected: `code` from a documented registry. Found by: code reading (`WebSqlEndpoints.Governance.cs`), confirm in WP2.

### PARITY-GAP-002
WebSQL answers unsupported capabilities with HTTP 501 `NotImplemented`, a 5xx. The PRD invariant says 4xx; D-9 tolerates 501 for now. Decide: map to 4xx with code, or document 501 as the contract. Confirm in WP2.
