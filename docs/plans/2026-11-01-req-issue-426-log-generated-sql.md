## 1. Problem Statement & Motivation

In Autheris v1.6.0, operators can configure `Gateway:Logging:LogGeneratedSql=true` (or configure per-data-source logging via `DataSourceProfileOptions.LogGeneratedSql`). This switch is intended to aid diagnostic workflows by logging the compiled SQL statement that Autheris generates after applying row-level security (RLS), column masking, and virtual filter pushdowns.

However, in practice, the generated SQL statement is always redacted:
```json
{"body":"GovernedTreeQueryService: Generated SQL: {Sql}","attributes":{"Sql":"[redacted]"}}
```

### Root Cause Analysis
1. In `GovernedTreeQueryService.cs`, `GovernedSqlRewriter.cs`, and `SqlProcedureRowScopeResolver.cs`, the logger is called with message templates containing attribute keys such as `{Sql}` or `{SecuredSql}`.
2. In `LogRedactionProcessor.cs:82-120`, `IsSensitiveKey(string key)` evaluates whether an attribute key should be redacted. It returns `true` for any key containing `"sql"`, `"query"`, `"filter"`, `"parameter"`, etc.
3. Because `{Sql}` and `{SecuredSql}` match `key.Contains("sql", StringComparison.OrdinalIgnoreCase)`, the value is unconditionally replaced with `"[redacted]"`.
4. There is currently no approved mechanism or setting that allows the parameterized SQL statement to pass through `LogRedactionProcessor`.

### Business & Operational Impact
Operators and database administrators troubleshooting slow queries or index utilization cannot inspect:
- The exact `ORDER BY` clause and column directions chosen by `DefaultReadOrdering`.
- Sub-query join shapes and table expressions generated by the AST compiler.
- Compiled `OFFSET/FETCH` clauses and keyset seek expressions.
Without the generated statement structure, operators cannot run `EXPLAIN` or evaluate execution plans against the backing database without manually reconstructing the query.

## 2. Gatekeeper Qualification & Deduplication

### Catalog Deduplication Check (`docs/features/`)
- Existing capabilities:
  - `HierarchicalDataSourceTelemetryPolicyProvider` and `SourceCommandTelemetry` already support parameterized trace statements (`StatementTextMode.Parameterized`) with `SqlTextScrubber.TryScrub`.
  - `HierarchicalDataSourceOptionsResolver` already clamps `LogGeneratedSql` against `Telemetry:Redaction:AllowStatementText` (SEC-DS05-06).
  - However, structured ILogger logs emitted to stdout/JSON exporters pass through `LogRedactionProcessor`, which lacks an approved key or bypass for scrubbed statements.
- **Verdict:** Valid bug and telemetry gap. An enhancement to existing logging and redaction logic is required.

### Zero-Trust & Security Fit
- **OWASP API Security Top 10 & Sensitive Data Exposure:** Raw literal values and parameter values (passwords, tokens, customer names, credit card numbers, tenant identifiers) must **never** be logged.
- **Safe Architectural Pattern:**
  - The query text logged MUST be parameterized or scrubbed using `SqlTextScrubber.TryScrub`.
  - Parameter values must be omitted.
  - The attribute key used for logging the scrubbed statement must be an approved, non-sensitive telemetry attribute (e.g., using the `autheris.` namespace, such as `autheris.db.statement` or `TelemetryAttributes.DbQueryText` with an explicit exemption in `LogRedactionProcessor`).
  - Output is strictly gated by both `LogGeneratedSql=true` AND `Telemetry:Redaction:AllowStatementText=true`.
  - Include the cryptographic query hash (`autheris.db.query.hash`) in the log message to correlate with OpenTelemetry spans and audit records.

## 3. Scope & Requirements

### In Scope
1. **Approved Telemetry Attribute for Statement Text:**
   - Define a standardized attribute key (e.g., `TelemetryAttributes.DbQueryText` / `"db.query.text"` or `"autheris.db.statement"`) that is recognized by `LogRedactionProcessor` as non-sensitive when scrubbed.
   - Exempt this attribute from the generic `"sql"` / `"query"` string redaction rule in `LogRedactionProcessor.IsSensitiveKey`, provided it contains scrubbed/parameterized SQL.
2. **Parameterized / Scrubbed Statement Logging:**
   - In `GovernedTreeQueryService`, `GovernedSqlRewriter`, and `SqlProcedureRowScopeResolver`, format debug log entries with:
     - The scrubbed statement text (via `SqlTextScrubber.TryScrub`).
     - The query hash (`hashHex`).
     - The target data source name and dialect.
   - Never log raw parameter values.
3. **Safety Ceilings:**
   - Logging is only active when:
     - `LogLevel.Debug` or lower is enabled for the logger category.
     - `LogGeneratedSql` is `true` for the effective data source profile.
     - `Telemetry:Redaction:AllowStatementText` is `true` (enforced at startup and in `HierarchicalDataSourceOptionsResolver`).
4. **Length Bounding:**
   - Enforce a maximum statement length bound in the log processor (e.g., 4096 characters) to prevent log-flooding DoS from excessively large queries.

### Out of Scope
- Logging raw SQL parameter values or database credentials (strictly forbidden).
- Adding full statement text to permanent audit trail tables (`AUDIT_LOG_ENTRIES` stores hash and metadata only, compliant with GDPR Art. 15 / SEC 17a-4).
- Production-level default enablement (`LogGeneratedSql` remains `false` by default).

## 4. Acceptance Criteria

1. **AC-1 (Scrubbed SQL Visibility):** When `LogGeneratedSql = true` and category `Autheris.Application.Sql.Tree.GovernedTreeQueryService` is `Debug`, the debug log event contains the parameterized SQL statement rather than `"[redacted]"`.
2. **AC-2 (Literal Value Sanitization):** Any literal values in the query (strings, numbers, timestamps) are replaced by parameter placeholders (e.g. `@p0`) or scrubbed tokens; no sensitive literal values appear in the log output.
3. **AC-3 (Safety Ceiling Enforced):** If `Telemetry:Redaction:AllowStatementText = false`, the statement text is suppressed/redacted even if `LogGeneratedSql = true`.
4. **AC-4 (Default Safe):** When `LogGeneratedSql` is omitted or `false` (default), no SQL statement text is logged.
5. **AC-5 (Log Redaction Processor Integrity):** Other attributes containing sensitive keywords (such as `user_password`, `raw_query`, `filter_token`) continue to be strictly redacted to `"[redacted]"`.
6. **AC-6 (Query Hash Correlation):** The log entry includes the statement hash (`autheris.db.query.hash`), matching the hash in traces and audit events.
