## 1. Verified facts (current branch)

- The revoke logic exists three times per dialect, not once: `RevokeConsentAsync` (`*GovernanceRepository.Consent.cs`, PG 647, MSSQL 684, SQLite 1767), `RevokeSystemConsentAsync` (PG 752, MSSQL ~788, SQLite 307) and `RevokeConsentInTransactionAsync` (`*.ConsentGrants.cs`, used by `ReplaceConsentsAsync`). D1/D2/D4 are present in all copies, so DEF-02..04 cover all nine sites.
- D2: PG/MSSQL `TenantId.TryParse(raw) ? tid : LegacySingleTenant` (ConsentGrants 175-180, Consent.cs PG 671/780, MSSQL 707/815). SQLite `new TenantId(raw)` throws `ArgumentException` that echoes the raw value; `RevokeSystemConsentAsync` SQLite maps NULL to `LegacySingleTenant`. `CONSENTS.tenant_id` is `NOT NULL DEFAULT 'legacy-single-tenant'` in all three baselines, so the NULL branches are dead code.
- D1: `"REVOKE"` in PG/MSSQL (6 sites), `"REVOKED"` in SQLite (3 sites). No production reader, report filter, query or doc filters on either literal (grep of `src/`, `deploy/`, `docs/`); only `ConsentGrantDialectSecurityTests` (line 95-102) and arch test T-03 pin them. The rest of the decision vocabulary is past participle (`GRANTED`, `EXTENDED`, `APPROVED`, `APPLIED`, `UPDATED`, `PURGED`); ReBAC tuple removal and `GatewayEventModels.Decision` already use `"REVOKED"`.
- D4: PG/MSSQL `IsAuthorizedApproverForTableInternalAsync(table, actor, null, ct)` (`*.Catalog.cs` PG 1342, MSSQL 1361) opens its own pooled connection, so the approver read is outside the revoke transaction. SQLite `RevokeConsentAsync` runs target read and approver check before `BeginTransaction` (Consent.cs 1767-1819); SQLite `RevokeConsentInTransactionAsync` passes the connection but not the transaction.
- D3/DEF-01: SQLite `ReplaceConsentsAsync` invalidates the epoch but never queues `_metadataCache` eviction; SQLite evicts through `QueueMetadataInvalidation` + `ApplyMetadataInvalidations` (generation-guarded, applied on commit).
- Governed fail-closed exception type exists: `GatewaySecurityException(message, errorCode)`; `GatewayExceptionHandler` maps it to a fixed title via `GatewayDenialStatusMapper` (default 403 "Access denied.") and never echoes the message (ARCH-MNT-08).

## 2. Decisions (DEF)

1. **One revoke core per dialect (prerequisite of DEF-02..04).** `RevokeConsentAsync` becomes: open connection/write scope, begin transaction, `RevokeConsentInTransactionAsync`, epoch bump of the returned table, commit, post-commit invalidations (exactly what `ReplaceConsentsAsync` does for one id). The second copy in `*.Consent.cs` is deleted. `RevokeSystemConsentAsync` keeps its own body (system actor, `consentRequestId` match, no approver check, returns `bool`) but uses the shared helpers of decisions 2 and 3. Testable: arch test `Revoke_Entry_Points_Share_One_Core_Per_Dialect` (IL: `RevokeConsentAsync` calls `RevokeConsentInTransactionAsync`, contains no `ldstr "CONSENT_REVOKED"`).
2. **DEF-02 tenant resolution fails closed.** New `ConsentGrantSqlCore.ResolveConsentTenant(string? raw)` returns `TenantId` or throws the new sealed `ConsentTenantIntegrityException : GatewaySecurityException` (`Autheris.Domain/Exceptions`, `ErrorCode = "CONSENT_TENANT_INVALID"`, fixed message "The consent tenant value is invalid; the operation was refused.", never the raw value, no inner `ArgumentException`). NULL, empty and regex-invalid values all throw. Used by `RevokeConsentInTransactionAsync`, `RevokeSystemConsentAsync` and the extend paths (`extendTenant`, PG 892/913, MSSQL 926/946, SQLite 1955/1971) in all dialects; no `TryParse`, no `LegacySingleTenant` default remains in these methods. The transaction rolls back; nothing is revoked, no epoch bump, no `CONSENT_REVOKED` row. HTTP/GraphQL: 403 with the governed code via the existing denial mapper (no new status mapping).
3. **Refusal audit.** After rollback the repository writes one audit row in its own short transaction: `EventType = AuditEventTypes.ConsentTenantIntegrityRefused` (new, `"CONSENT_TENANT_INTEGRITY_REFUSED"`), `Decision = "DENY"`, `ActorSid = actor`, `TargetTable = table`, `DetailsJson = { ConsentId, Code }` (no raw tenant value), `TenantId = ConsentGrantSqlCore.IntegrityAuditTenant` (one named property, today `=> TenantId.LegacySingleTenant`, the existing bucket for tenant-less platform events such as `AuthFailureAggregator`; it is the explicit audit bucket, not a fallback for the consent's tenant, and the single replacement point for the `refactor/default-tenant` lane; no new sentinel in this PR). An audit write failure propagates `AuditUnavailableException` (fail closed, the revoke is already refused). The refusal is also logged at Warning with the code and consent id only.
4. **DEF-03 literal: `"REVOKED"`.** Chosen because it matches the past-participle decision vocabulary, matches ReBAC and `GatewayEventModels`, and no reader depends on `"REVOKE"`. One `const string ConsentGrantSqlCore.RevokedDecision = "REVOKED"` (a C# `const`, so the literal stays in the IL and in the golden) is used at all nine sites. Release note: PG/MSSQL audit rows written after this change carry `REVOKED`; old rows keep `REVOKE` (no repair migration, owner rule 2026-10-15).
5. **DEF-04 approver check inside the transaction.** PG/MSSQL `IsAuthorizedApproverForTableInternalAsync` gets an overload `(conn, tx, table, approverSid, itsmAccount, ct)` that sets `cmd.Transaction = tx` on the owner, delegate and role commands; the existing overload opens a connection and delegates to it. SQLite overload gains the `SqliteTransaction tx` parameter. The call is made after `ReadRevokeTargetAsync` (row lock: PG `FOR UPDATE OF c`, MSSQL `UPDLOCK, ROWLOCK`, SQLite write scope) in every dialect. No extra lock on `DATA_OWNERS`/delegations (revoke reduces access; read-committed under the consent row lock is sufficient; Phase 3 question P-2).
6. **DEF-01.** SQLite `ReplaceConsentsAsync` calls `QueueMetadataInvalidation(table)` for each table inside the transaction (applied on commit), like PG/MSSQL `_metadataCache.TryRemove`. Test `ReplaceConsents_Sqlite_Evicts_MetadataCache`.
