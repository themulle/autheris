## Invariants that must not regress

- I1 (#813/#817): every object on a page and every object counted by `q` passes the per-caller visible text check (`KeepCallerVisibleMatchesAsync`); no hidden text, no NoAccess column names.
- I2 (#871/#865): a person sees only `Clear`/`Masked` columns (`DiscoveryColumnVisibility`); filters over columns (`pii`) evaluate visible columns only.
- I3 (#831/#798): `accessStatus` narrows the set before `totalCount` and the cursor; app-only callers get 400 for `accessStatus` and `q`.
- I4 (#880): a cursor is valid only for the filter set it was issued for; a mismatch is `400 INVALID_CURSOR`.
- I5: tenant isolation (`LoadScopedCatalogAsync` scope memo per tenant and caller; `DiscoveryTenantScope`).

## Root cause (#894, verified on main)

- `ExternalCatalogReader.ListObjectsAsync` (ExternalCatalogReader.cs:64-126) reads all tables (`LoadContextAsync`, :266-277), then `BuildUserCatalogObjectsAsync` (:368-415) loops `IDiscoveryService.ListAsync` with `First = 200` until the end. Each round projects 200 objects (`ResolveObjectsBatchAsync`, DiscoveryService.cs:615: PDP decisions, column projection) and writes one discovery audit (DiscoveryService.cs:210). Every object is then mapped to a DTO, and only after that are the objects sorted, filtered (`ApplyFilters`, :724-780) and offset-paged (:111-122).
- `DiscoveryService.ListAsync` itself is already page-shaped (DiscoveryService.cs:189-204). The cost comes from the reader's loop over every page and from DTO mapping before paging.

## Decisions

1. **Keyset over the scoped catalog, projection per page (default taken).** The metadata-level filters and the sort run in memory over `ScopedCatalog.VisibleTables` (already tenant- and hidden-scoped, metadata from the cached keyset repository reads of #677). Only the page is projected (PDP, columns, audit, DTO, row scope). No SQL-side visibility rewrite: the visibility rules (tenant scope, hidden ownership, consents) stay in one place. The remaining O(catalog) metadata pass is #677's scope (snapshot as the listing source).
2. **Stable sort key:** `TableIdentifier.ToString()` with `StringComparer.OrdinalIgnoreCase`, tie-break `StringComparer.Ordinal`. This is a total order and matches today's `OrderBy(ObjectId, OrdinalIgnoreCase)`.
3. **Filter classes.** *Pre-projection* (pushed down, exact count): `domain`, `schema`, `kind` (`Table.ObjectKind`), `tag` (the same union as `MergeTags`), `sensitivity` (`Table.Sensitivity`, the DiscoveryAccessMapper.cs:133 source), `changedSince` (change-store versions), `accessStatus` (set-based `LoadAccessViewAsync`, DiscoveryService.AccessState.cs:44). *Post-projection* (evaluated on projected windows): `q` restricted-object verification (I1), `pii` over visible columns (I2), `owner`.
4. **Page fill.** The page fill walks the ordered candidates after the cursor key in windows of `min(pageSize + 1, 200)`, projects each window and keeps matches until it has `pageSize + 1` or the candidates run out. The extra item only sets `nextCursor`. With no post-projection filter, exactly one window is projected.
5. **`totalCount` (default taken).** If the filter set has only pre-projection filters, `totalCount` is the exact count of the filtered candidate keys (no projection) on every page. If it has a post-projection filter, the first page (no cursor) runs one verification pass over the pre-filtered candidates only. That pass uses projection without DTOs, artifacts or row scope. The exact count goes into the cursor and later pages echo it. No server-side count cache and no estimate flag; the contract stays unchanged.
6. **Cursor v2 (default taken).** The cursor is `PageCursor.Encode("v2|<lastKey>|<count?>|<binding>")`. The binding is a truncated SHA-256 over every filter (`q`, `accessStatus`, `kind`, `domain`, `schema`, `owner`, `tag`, `sensitivity`, `pii`, `changedSince`), the tenant id and the caller scope key hash. This extends #880's `ComputeCursorBinding`. Offset cursors and v1 cursors return `400 INVALID_CURSOR` (no production yet). A cursor is never an authority: a forged key only sets the position inside the caller's own visible set.
7. **Audit (default taken):** one discovery audit per request, covering the objects returned on the page. Today it is one per 200-object round, covering all objects.
8. **App-only path:** the same keyset and page mapping run over `FilterInScopeTablesAsync` + hidden rule. Owners and artifacts are loaded for the page only (ExternalCatalogReader.cs:334-366).
9. **Out of scope:** `GET /objects/{id}` (1.5 s) and `/catalog/search` (2 s) still use `LoadContextAsync` / full scoped load. These go to #677 (by-identifier reads). #681 (MCP `list_datasets`) reuses the new keyset primitive afterwards (`McpDatasetCatalog`). The pointer is recorded in the catalog-scale plan.
10. **#896 kind sources (default taken):** dbt model `config.materialized == "view"` gives `View`. Every other materialization (`table`, `incremental`, `materialized_view`, `snapshot`, `seed`) gives `Table`. dbt sources and objects without a dbt model take `meta.autheris.object_kind` (`view` or `table`; any other value: `Table` plus a sync warning). Semantic virtual tables are `View`, matching TrinoMetadataQueryHandler.cs:245. There is no live source-catalog introspection: main has no source-catalog reader (the physical key catalog was removed in the simplification programme), and adding an outbound catalog query is its own security-relevant feature, so it goes to a follow-up issue filed with this plan's Phase 3. OpenAPI-ingested objects stay `Table`.
11. **#896 persistence:** `object_kind` is not stored (`"Table.ObjectKind"` is `notWritten`, CatalogTablePersistedProjection.cs:422). A forward-only governance step adds `TABLES.object_kind VARCHAR(16) NOT NULL DEFAULT 'table'` with `CHECK (object_kind IN ('table','view'))`. The step number is the next free one at merge: `0029` on main, but the open branch `feat/simpl-52-drop-role-grantee` also takes `0029`, so whichever merges second renumbers. The step needs PostgreSQL + SQL Server SQL and `.shape.json`, and goldens in `tests/Autheris.Tests.Architecture/Golden/GovernanceSteps/checksums.{postgresql,sqlserver}.txt`. Existing rows read `table` until the next sync.
12. **#896 merge rule (default taken):** the incoming sync is the source of truth. `CatalogGovernanceRatchet.cs:71` takes `inTable.ObjectKind`, so a view that becomes a table goes back to `Table`. Kind is descriptive only. It is never an authorization input, and the write state is unchanged (DiscoveryAccessMapper.cs:254 tests `Procedure` only).
13. **#898 facets (default taken):** new `GET /api/v1/catalog/objects/facets?accessStatus=` returns `{ totalCount, domains: [{ domain, count, schemas: [{ schema, count }] }] }`, sorted by domain, then schema (ordinal ignore case). It is computed over the same candidate set as decision 3 with no projection, so the sum equals `/catalog/objects` `totalCount` for the same `accessStatus`. Procedures are excluded, as in the list. App-only callers: allowed without `accessStatus` (400 with it, as in the list). The literal `/objects/facets` route wins over `/objects/{id}`; object ids always contain a dot or are GUIDs.
14. **#898 `/catalog/domains` (default taken):** keep the route and response shape (`totalTables`, `totalDomains`, `domains[{domain, tableCount}]`). It delegates to the facet computation (no 200 cap), with `CatalogDiscoveryApiHelpers.ListDomainsAsync` (CatalogDiscoveryApiHelpers.cs:98-119) no longer calling `ListDatasetsAsync`.
15. **Endpoint ratchet:** the endpoint count goes from 340 to 341 (`Baselines/endpoint-count.txt`). The PR carries the `freeze-exception` label with the #898 link; this plan row is the owner mandate. No `ingress-exemptions.txt` entry is needed: the route sits in the `/api/v1/catalog` group with `WithIngressTransport(Rest)` (CatalogApiEndpoints.External.cs:32-33).

## Threats for Phase 3

- T1 cursor forgery or replay: a forged key, a cross-filter, cross-tenant or cross-caller replay, or a stale cursor must not reveal hidden objects or another caller's count (decision 6 binds tenant and caller scope hash). Required: a `[Trait("Category","Security")]` test for each.
- T2 count oracle: `totalCount`, facet counts and `/catalog/domains` counts come only from the caller-visible set after the hidden, tenant and `accessStatus` filters. A hidden object or a foreign-tenant object must never change a number.
- T3 `q` count pass and page fill (I1): restricted objects are counted or listed only after visible-text verification. The count pass must use the same verifier as the page.
- T4 `pii` over hidden columns (I2): a NoAccess PII column must not make `pii=true` match or count.
- T5 audit semantics change (decision 7): fewer objects are audited per request. Confirm this is acceptable for the discovery audit trail.
- T6 facets endpoint: read-only token GET, `CatalogRead` policy, `DiscoveryCallerGate` rate limit, route shadowing of `/objects/{id}`, and response size (one entry per domain/schema; consider a cap of 10,000 schemas with a `truncated` flag — default taken: no cap, because the response is bounded by the visible catalog).
- T7 kind import: `meta.autheris.object_kind` is supplied by the ClusterAdmin sync. Values are validated against a closed set, the CHECK constraint backs this, and kind never becomes an authorization input (decision 12).
- T8 migration: the forward-only step is idempotent (`IF NOT EXISTS` / `COL_LENGTH` guard), checksum goldens are updated in the same PR, and the step number does not collide at merge.
