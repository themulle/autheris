## 2. Architecture Decisions

### A-1 GraphQL SDL (binding; exact types)

Shared types (registered once in `CatalogGraphQlTypeModule.CreateTypesAsync`):

```graphql
enum AutherisAggregateFn { COUNT  COUNT_DISTINCT  SUM  AVG  MIN  MAX }

"Declared type of a value; stable per alias, independent of the value being null."
enum AutherisValueKind { STRING  INT  DECIMAL  FLOAT  BOOLEAN  DATE_TIME }

"Exactly one *Value field is set (the one named by kind); all are null when the aggregate is NULL (for example SUM over no non-null rows)."
type AutherisAggregateValue {
  alias: String!
  kind: AutherisValueKind!          # never BOOLEAN
  intValue: Long                    # kind INT
  decimalValue: Decimal             # kind DECIMAL
  floatValue: Float                 # kind FLOAT
  stringValue: String               # kind STRING
  dateTimeValue: DateTime           # kind DATE_TIME (UTC, ISO 8601)
}
```

Decision on Q-112-1 (the shape the owner left to the architect): **group columns as typed fields of a per-table key object, aggregates as a list of `AutherisAggregateValue`** with the owner's four value fields plus `floatValue` and an explicit `kind`. Justification: (1) the schema is static and global (`Schema_IsIdenticalForAllCallers`, `CatalogGraphQlSchemaTests.cs:710`), aliases are free text, so aggregate values cannot be fields; (2) one nullable field per kind lets a TypeScript client generate `{ alias: string; kind: ...; intValue?: number | null; ... }` and read exactly `kind`'s field without inspecting runtime values; (3) `floatValue` is added because a `Float` column's SUM/AVG/MIN/MAX must not be forced into `Decimal` (NaN/precision); (4) a `@oneOf` output does not exist in GraphQL and a union of scalars is impossible, so the tagged-record shape is the equivalent typed form; (5) precision note for Phase 6 docs: `Long` and `Decimal` serialize as JSON numbers (same as the existing entity types, `CatalogGraphQlTypeModule.cs:324-334`), so JavaScript clients lose precision above 2^53.

Per table `T` (`T` = `CatalogTableType.TypeName`; all names derived by one static helper `AggregateTypeNames.For(T)`, the record `CatalogTableType` is **not** changed, so `CatalogSchemaModelTests` constructors stay valid):

```graphql
"Column field names of T, spelled exactly like the fields of the entity type T."
enum T_column { <fieldName1>  <fieldName2> ... }       # a field named true/false/null becomes <name>_col (GraphQL forbids those enum values)

input T_aggregate_input    { fn: AutherisAggregateFn!  column: T_column  alias: String! }
input T_aggregate_order_by { column: T_column  alias: String  direction: AutherisSortDirection! = ASC }   # exactly one of column / alias (validated, error AGGREGATION_ORDER_INVALID)

"Typed group key: one nullable field per column, filled only for columns named in groupBy, all null on the merged OTHER row."
type T_aggregate_key   { <fieldName>: <GetScalarName(columnType)> ... }      # same scalar mapping as the entity type, DateTime columns stay String (R-GQL-10 behaviour)
type T_aggregate_group { key: T_aggregate_key!  rowCount: Long!  isMergedOther: Boolean!  aggregates: [AutherisAggregateValue!]! }
type T_aggregate_result {
  groups: [T_aggregate_group!]!
  count: Long!                       # row count over the visible (post-suppression) groups only
  suppressed: Boolean!  suppressedGroupsCount: Int!  suppressedRowsCount: Long!  minimumGroupSize: Int!
  mergedIntoOther: Boolean!  truncated: Boolean!  noiseApplied: Boolean!
}

extend type Query {
  T_aggregate(groupBy: [T_column!], aggregates: [T_aggregate_input!]!, where: T_filter,
              orderBy: [T_aggregate_order_by!], limit: Int = 100): T_aggregate_result!
}
```

Removed: `AutherisAggregationResult` (including `groupsJson`), the arguments `groupBy: [String!]` and `where: String` (Q-112-2). `T_filter` is reused unchanged (typed, variables). `AutherisValueKind.BOOLEAN` is used only by metric dimension values (A-8). Schema size: six new type members per table (column enum, key, group, result, two inputs); an SDL-growth assertion test records the delta for a 50-table x 20-column catalog (risk R-2).

### A-2 Alias and argument rules (resolver, before the engine)

`alias` must match `^[A-Za-z_][A-Za-z0-9_]{0,63}$`, be unique case-insensitively (the engine's dictionaries are `OrdinalIgnoreCase`), not collide with any group column name or field name, and not be `count` or start with `__` (reserved: `count` and `__n` are the engine's group-count aliases, `GovernedTableReadPlanner.cs:42`, `GovernedAggregationService.ValidationAndExecution.cs:279-283`). `aggregates` must contain 1..`MaxAggregates` items, `groupBy` 0..`MaxGroupByColumns` distinct columns, `limit` 1..`MaxGroups` (`<= 0` is an error, a value above the cap is clamped by the engine as today, `GovernedAggregationService.cs:183-188`). Errors: `AGGREGATION_ALIAS_INVALID`, `AGGREGATION_ARGUMENT_INVALID`, `AGGREGATION_LIMIT_EXCEEDED` (limit above `UpperBoundMaxGroups`), fixed messages without echoing the client value.

### A-3 Typed filter to `TableFilterClause` (one builder, shared by both fields)

New `Application/Sql/Tree/TreeFilterClauseBuilder` (static, pure): `Build(TreeFilter filter, Func<string, ColumnRef?> resolveColumn) -> TableFilterClause`. It renders Trino syntax, quoted catalog column names, **every value as a named `@pN` parameter**, `1 = 0` / `1 = 1` for empty OR / IN lists, `LIKE ... ESCAPE '!'` with `!`-escaping of `!`, `%`, `_` exactly like `ODataFilterParser` (`ODataFilterParser.cs:780-850`; note: the tree compiler's `EscapeLike` (`TreeSqlCompiler.cs:803-806`) escapes with `\` and `[`, which Trino rejects, so it cannot be reused verbatim). The pure shape logic (AND/OR/NOT nesting, IN limit `MaxInListSize`, depth limit `MaxFilterDepth`, null rules) is extracted from `TreeSqlCompiler.BuildFilter/BuildComparison` (`:719-781`, `:444-467`) into a small `TreeFilterRenderer` that both the tree compiler (dialect quoting, behaviour unchanged, `TreeSqlCompilerTests` stay green) and the new builder call. Output contract:

- `SqlPredicate` = the Trino predicate text (so any consumer that reads only `SqlPredicate` sees the same canonical text, F-7), `TrinoSqlFactory` returns it, `Parameters` holds typed CLR values, `ReferencedColumns` is the **exact** set of columns in the tree (F-8).
- The text never contains a literal; a unit test asserts this over all operators (it also protects the audit field `filter`, `GovernedAggregationService.cs:178,328`).
- Value typing: the GraphQL layer coerces values with the existing `CoerceValue` (kept as thin wrappers in `GraphQlTreeBuilder` so `DateCoercionRGql10Tests` and `GraphQlTreeBuilderCultureTests` stay unchanged) after the logic moves to an Application-level `FilterValueCoercion` keyed by a new Application enum `ColumnValueKind { String, Int, Long, Float, Decimal, Boolean, DateTime }`; `CatalogSchemaModel.MapDataType` delegates to `ColumnValueKind.FromDataType` (same function body, moved).
- Compatibility test (first red test of WP-1): every operator's `SqlPredicate` must also evaluate in `InMemoryRowFilterEvaluator.FilterRows(rows, sqlPredicate, metadata, parameters)` because the executor branch uses it (`ValidationAndExecution.cs:421`). If the evaluator rejects `ESCAPE '!'`, the clause additionally sets `DialectSqlFactory` and `SqlPredicate` uses the evaluator's accepted form while `TrinoSqlFactory` keeps the Trino form; the developer decides by the test.

For `<table>_aggregate` the GraphQL resolver parses `where` into `TreeFilter` (reusing `ParseObjectFilter` made `internal static` for that purpose) and calls the builder with the table's column map; for `queryMetrics` the builder runs inside `SemanticMetricQueryService` after the table is resolved (A-8).

### A-4 Result mapping, kinds, suppression counters

New `GraphQL/Catalog/AggregateResultMapper` (pure, unit-tested):
- **Kinds are static**, from function and column type (matrix below), so a `NULL` value still has a correct `kind`.

| Function | Column type (`CatalogFieldType`) | `kind` | Notes |
|---|---|---|---|
| COUNT | none or any | INT | `COUNT` without column = `COUNT(*)`; with column = non-null count |
| COUNT_DISTINCT | any, column required | INT | |
| SUM | Int, Long | INT | engine returns `decimal`; converted checked, non-integral or overflow -> error |
| SUM | Decimal / Float | DECIMAL / FLOAT | |
| AVG | Int, Long, Decimal / Float | DECIMAL / FLOAT | |
| MIN, MAX | Int, Long / Decimal / Float / DateTime / String | INT / DECIMAL / FLOAT / DATE_TIME / STRING | |
| any other combination (SUM/AVG/MIN/MAX on Boolean, SUM/AVG on String/DateTime, missing column) | | rejected | `AGGREGATION_INVALID_FUNCTION_FOR_TYPE` (decided on `CatalogFieldType`, stricter than the engine's `IsNumericType` string match, `GovernedAggregationService.Buckets.cs:590-607`, which accepts e.g. `point` because it contains "int") |

- Conversion is strict and invariant-culture; a driver value that cannot be converted to the declared kind raises `AGGREGATION_RESULT_TYPE_MISMATCH` (fixed message, no value) instead of returning null or a string.
- Rows with `IsMergedOther` set `isMergedOther = true` and **null** key fields; `COUNT_DISTINCT` and `AVG` of that row are null (F-3).
- `suppressedGroupsCount` and `suppressedRowsCount` are both reported as `0` when `Analytics:Privacy:ExposeSuppressedGroupsCount` is `false` (F-9); `suppressed` stays.
- `count` = `Totals.Count` of the engine result (computed over the surviving groups only, `GovernedAggregationService.cs:307-308`).

### A-5 Engine corrections (shared by REST, MCP and GraphQL; one engine)

All in `Application/Analytics`, behaviour-preserving except where listed in section 8:

1. **Routing (F-1).** `ExecuteAndBuildBucketsAsync`: when `_sqlExecutionService != null` and the table's `DataSourceType` is `Sql`, use the planner branch (`:354-388`); executors stay for non-SQL sources and for the no-SQL-service case (all current unit tests construct the service without `sqlExecutionService`, so they keep the executor branch). The executor branch fails closed when it receives the row cap (`rows.Count >= 100_000`): `GatewaySecurityException("AGGREGATION_ROW_CAP_EXCEEDED")`, never a silently truncated aggregate.
2. **Honest truncation (F-2).** The planner is asked for `sqlLimit + 1` rows; if more come back the extra row is dropped and `truncated = true`. SQL ordering stays as planned; the in-memory ordering and `Take(requestedLimit)` after suppression stay (`GovernedAggregationService.cs:274-284`), which is the property FR-112-5 needs.
3. **Merged rows (F-3).** `MergePreAggregatedBuckets` returns `null` for `CountDistinct` and `Avg` (documented "not computable from pre-aggregated groups"); the in-memory merge from raw rows (`ComputeBucketFromRows`, `:253-255`) stays exact. This also changes the REST merged-row values (section 8).
4. **Uniform column errors (F-4).** New `AggregationColumnUnavailableException : GatewayInvalidQueryException` (code `AGGREGATION_COLUMN_UNAVAILABLE`, fixed message without the column name) replaces the unknown-column `ArgumentException` and the denied-column `GatewayForbiddenException` in `ValidateAndResolveGroupBy`, `ValidateAndResolveAggregates`, `ValidateWhereClause`, `ValidateOrderByClause` (and the planner's equivalents stay as defence in depth). `MaskedAggregationException` is unchanged (a masked column is already visible as a field, acceptance 3 keeps `AGGREGATION_ON_MASKED_COLUMN`). The audit reason uses the same fixed text; the column name goes to the structured audit fields `group_by` / `aggregates` as today.
5. **Noisy cache key (F-5).** `BuildNoisyCacheKey` appends the canonical parameter set (`name=<invariant value>` sorted by name) of `query.Where.Parameters`.
6. `AggregationQuery.Transport` is `"graphql"` for the field (existing `CatalogGraphQlTypeModule.cs:521`) and `"SemanticMetrics"` for metrics (`SemanticMetricQueryService.cs:~245`); FR-112-10 is already met, a test pins both labels in the audit entry.

### A-6 Authorization and validation order (fail closed)

Per call, in this order and stopping at the first failure: authenticated principal (existing `UNAUTHORIZED`) -> argument shape (A-2) -> function/type matrix (A-4) -> `ValidateBounds` (`AggregationCostCalculator.cs:45-85`, includes `Analytics:Aggregation:Enabled`) -> table lookup and decision (`GovernedAggregationService.cs:133-153`; denied table keeps `ACCESS_DENIED`) -> column checks (`AGGREGATION_COLUMN_UNAVAILABLE` / `AGGREGATION_ON_MASKED_COLUMN`) -> execution -> suppression -> ordering -> limit -> DP noise. The resolver never decides access; it only shapes the request. Row filters and the tenant predicate are applied by the governed SQL pipeline before aggregation (planner path, F-1 fix); the executor path applies `InMemoryRowFilterEvaluator` before bucketing (`:335-337`).

### A-7 Cost model (FR-112-6)

`QueryCostAnalyzerRule.CalculateSelectionSetCost` currently treats the aggregate field like any paginated payload because it has a `limit` argument (`QueryCostAnalyzerRule.cs:154-158`, `:262-330`), so cost ignores `groupBy` and `aggregates`. Add one special case before the generic branch: a field whose name ends in `_aggregate` and whose return type name ends in `_aggregate_result` costs `AggregateFieldCostWeight + 10 * groupByCount + sum(5 | 15 for COUNT_DISTINCT)` (the `AggregationCostCalculator` weights, `:12-14`), with counts from literals or runtime variable values; when `groupBy` or `aggregates` cannot be resolved (variable without value) the worst case `MaxGroupByColumns` / `MaxAggregates` with `CountDistinctWeight` is assumed. The selection set below the field (`groups`, `key`, `aggregates`) is **not** multiplied again (the field cost already models it). `QUERY_TOO_COMPLEX` is the error code (existing rule). The rule receives the three option values through its constructor (new optional parameters with the current defaults, so existing constructions compile).

### A-8 Typed `queryMetrics`

Decision on FR-112-8: a **generic typed filter shape, not a per-metric or per-model generated input**. Per-model types would be built from tenant manifest data while the schema is global and identical for all callers (`CatalogGraphQlSchemaTests.cs:710`), which would leak model and dimension names across tenants and force a schema rebuild on every import. SDL:

```graphql
input AutherisTypedFilter @oneOf {            # @oneOf via d.OneOf(); if unavailable in HC 16.6.8: nullable fields + "exactly one" check (error METRIC_FILTER_INVALID)
  string: AutherisStringFilter  int: AutherisIntFilter  long: AutherisLongFilter  float: AutherisFloatFilter
  decimal: AutherisDecimalFilter  boolean: AutherisBooleanFilter  dateTime: AutherisDateTimeFilter
}
input AutherisDimensionFilter { name: String!  where: AutherisTypedFilter! }
input AutherisMetricFilter { and: [AutherisMetricFilter!]  or: [AutherisMetricFilter!]  not: AutherisMetricFilter  dimension: AutherisDimensionFilter }
input AutherisMetricOrderBy { dimension: String  metric: String  direction: AutherisSortDirection! = ASC }   # exactly one of dimension / metric

extend type Query {
  queryMetrics(metrics: [String!]!, groupBy: [String!], where: AutherisMetricFilter,
               timeGranularity: String, orderBy: [AutherisMetricOrderBy!], limit: Int): AutherisMetricQueryResult!
}

type AutherisDimensionValue { name: String!  kind: AutherisValueKind!  stringValue: String  intValue: Long  decimalValue: Decimal
                              floatValue: Float  booleanValue: Boolean  dateTimeValue: DateTime }

                           values: [AutherisAggregateValue!]! }       # alias = metric name, in the order of the requested metrics
type AutherisMetricDefinition { name: String!  type: String!  label: String  description: String  unit: String }
type AutherisMetricQueryResult {
  metrics: [String!]!  manifestVersion: String!  groups: [AutherisMetricGroup!]!  count: Long!
  suppressed: Boolean!  suppressedGroupsCount: Int!  suppressedRowsCount: Long!  minimumGroupSize: Int!
  mergedIntoOther: Boolean!  truncated: Boolean!  noiseApplied: Boolean!

```

Mechanics: `MetricQueryRequest` gets `TypedWhere: TreeFilter?` next to the legacy `Where` (MCP and REST keep `Where`; both set -> `ArgumentException`). `SemanticMetricQueryService` builds the clause **after** `ResolveTableMetadataAsync` (`SemanticMetricQueryService.cs:164`) with `TreeFilterClauseBuilder`, checking each leaf's typed filter kind against the resolved column's `ColumnValueKind` (`string` filter on an Int column -> `METRIC_FILTER_INVALID`); an unknown/denied dimension name raises `AggregationColumnUnavailableException`. `CombineMetricFiltersWithWhere` is changed to compose through `requestWhere.GetTrinoPredicate(...)` and to merge `Parameters` with a collision check (F-7). `MetricQueryResult` gains `MetricValueKinds` and `DimensionValueKinds` (computed in the service from measure aggregation, column type and metric type; ratio/derived metrics are `DECIMAL`, counts `INT`) so the mapper needs no table access. The dead `AnalyticsQueryExtensions.QueryMetricsAsync` and its duplicate on `Query` are replaced by **one** definition on `Query`; the static `ExecuteQueryMetricsAsync` is rewritten; the unit test at `DifferentialPrivacyNoiseAndGraphQlMetricsTests.cs:318-348` is rewritten against the new signature. Error mapping at the GraphQL boundary: `KeyNotFoundException` (unknown metric) and any `GatewayForbiddenException` raised by the metric consent decision (`SemanticMetricQueryService.cs:176-195`) both map to `UNKNOWN_METRIC` with the fixed message "The metric is not available." (anti-oracle, consistent with F-DBT-07 "rejected as not found"); `MaskedAggregationException`, `PrivacyBudgetExhaustedException`, `AggregationColumnUnavailableException` keep their own codes. `manifestVersion` is the tenant's persisted version (A-9).

### A-9 Persisted, tenant-scoped semantic manifest (FR-112-9, SI-112-5/6)

- **Store:** one row per tenant holds the validated manifest as JSON (latest version only, Q-112-3). A single-statement upsert makes an import atomic (the whole manifest replaces the previous one; removed metrics disappear). Interface `Application/Dbt/Interfaces/ISemanticManifestStore` (`GetAsync(TenantId)`, `SaveAsync(TenantId, StoredSemanticManifest)`), implemented as a partial of the three governance repositories (pattern of `ICdcWatermarkRepository`, `RegisterGovernanceAggregateStores`, `GatewayGovernanceServiceExtensions.cs:195-236`).
- **Catalog:** new `PersistentSemanticCatalog : ISemanticCatalogService` (Application/Dbt/Services) = per-tenant read-through cache over the store: lazy load on first access (single-flight per tenant), `Semantic:ManifestCacheSeconds` (default 30) re-check of `manifest_version + content_hash` for other nodes, local invalidation on save. "Reloaded at startup" is therefore satisfied on the first request after a restart without loading all tenants eagerly (5,000-user scale target). A row that fails to deserialize or has an unknown `format_version` is treated as "no manifest" with one Error log (fail closed: unknown metric), never a startup failure. `InMemorySemanticCatalog` remains for tests and for `Semantic:PersistManifest = false`.
- **Tenant-explicit (F-6):** the non-tenant members are removed from `ISemanticCatalogService` (the tenant overloads become the interface; `ManifestVersion` becomes `GetManifestVersionAsync(TenantId)`); callers are fixed: `SemanticMetricQueryService` (`:112`, `:117`) uses the principal's tenant, `DbtEndpoints` semantic-manifest and metrics routes use `EndpointSecurity.GetRequestTenant(context)` (`:364`, `:386-393`), `AnalyticsEndpoints` list route and `McpSemanticTools`/`McpToolExecutionHandler` pass their tenant. The legacy-partition fallback in `ResolvePartition` is deleted: a tenant sees only its own manifest (`TenantId.LegacySingleTenant` is just another tenant id, which is what single-tenant installs resolve to, `Sid.cs:166-185`).
- **Import validation (SI-112-5):** `SemanticManifestValidator` runs before any side effect: model count <= 1,000, metric count <= 5,000, names match `^[A-Za-z0-9_.\-]{1,128}$` and are unique case-insensitively, string fields <= 4,096 chars without control characters, every metric measure/dimension reference resolves inside the manifest, `min_group_size >= 1`, allowed granularities within the standard set. `filter` templates (manifest text executed later through the governed compile path) are parse-checked with the engine's statement parser on `SELECT 1 FROM t WHERE <cleaned filter>`; if no public parse entry exists the developer limits this to structural checks and records the residual risk for Phase 3. Failure returns `DBT_MANIFEST_INVALID` and changes nothing. Order inside `DbtSemanticManifestIngestionService`: parse -> validate -> persist and swap the cache (atomic) -> idempotent virtual-table upserts (`:251-`); a failure in the last step is logged, answered with `500 DBT_MANIFEST_PARTIAL`, and a re-import repairs it.
- **Authorization (Q-112-3):** unchanged: `GovernanceAdmin`/`ClusterAdmin` or `DbtAdmin` (`DbtEndpoints.cs:346-350`). Audit unchanged (`AuditConfigChanged`, Full) plus the new detail fields `manifest_version`, `content_hash`, counts.
- **Persisted content is data (SI-112-6):** the store never grants access; every metric query still resolves its base table through `ResolveTableMetadataAsync` and the consent decision (`SemanticMetricQueryService.cs:164-195`).

## 6. Fail-Closed Behaviour

| Situation | Outcome |
|---|---|
| Unauthenticated, no user SID | `UNAUTHORIZED` / engine `GatewayUnauthorizedException` (existing) |
| Table denied by decision | `ACCESS_DENIED`, no partial rows |
| Unknown or denied column anywhere (`groupBy`, aggregate column, `where`, `orderBy`) | identical `AGGREGATION_COLUMN_UNAVAILABLE` |
| Masked column anywhere, including `COUNT_DISTINCT`/`MIN`/`MAX` and `where` | `AGGREGATION_ON_MASKED_COLUMN` |
| Function not valid for the column type, alias invalid, argument shape wrong | fixed-message validation errors, no engine call |
| Row cap reached on the executor path | `AGGREGATION_ROW_CAP_EXCEEDED`, never a truncated aggregate |
| SQL group limit cut | `truncated = true` |
| Typed conversion of a result value fails | `AGGREGATION_RESULT_TYPE_MISMATCH` (no value in the message) |
| Privacy budget exhausted (noise enabled) | `PRIVACY_BUDGET_EXHAUSTED` |
| Unknown metric or no consent for the metric | the same `UNKNOWN_METRIC` |
| No manifest for the tenant, corrupt row, unknown `format_version` | metrics unknown (empty catalog), Error log, no startup failure |
| Manifest fails validation or persistence | nothing changes (previous manifest stays active) |
| `ISemanticManifestStore` missing while `PersistManifest = true` | startup validation failure |
| `GraphQL:Aggregation:Enabled = false` or `Analytics:Aggregation:Enabled = false` | field absent / `Governed aggregation queries are disabled by configuration` |

## 8. Breaking-Change and Behaviour-Change List

**GraphQL (owner-approved breaking, Q-112-2):**
1. `<table>_aggregate`: arguments `groupBy: [String!]` and `where: String` removed; new typed arguments (A-1); result type `AutherisAggregationResult` removed and replaced by per-table `<table>_aggregate_result`; `groupsJson` removed (typed `groups`); result field `count` keeps its meaning; `suppressed*` fields keep names.
2. `queryMetrics`: `where: String` and `orderBy: [String!]` replaced by typed inputs; the result type changes from the inferred `MetricQueryResult` to `AutherisMetricQueryResult` (dictionaries of `object` -> typed lists; `metricDefinitions` reduced to name/type/label/description/unit; `totals` removed from the GraphQL result).
3. The unregistered duplicate `AnalyticsQueryExtensions` is deleted (its unit test is rewritten).

**Behaviour changes visible on other transports (engine is shared):**
4. Denied (not masked) columns in aggregations now answer `AGGREGATION_COLUMN_UNAVAILABLE` (400) instead of a 403 `GatewayForbiddenException`, and unknown columns use the same code (REST `POST /api/v1/analytics/aggregate` and metrics, MCP).
5. Merged `OTHER` rows return `null` for `COUNT_DISTINCT` and `AVG` on the SQL path (was a wrong sum / row-count-weighted mean).
6. SQL tables now aggregate through the SQL planner (correct beyond 100,000 rows, filters pushed down); the executor branch fails with `AGGREGATION_ROW_CAP_EXCEEDED` instead of truncating silently; `truncated` is now set when the SQL group limit cuts groups.
7. Semantic catalog: manifest import **replaces** the tenant's manifest (was additive merge); import, listing and query are **tenant-scoped** (was legacy partition for everyone); the legacy-partition fallback for other tenants is removed (a tenant that never imported has no metrics); `GET /api/extensions/dbt/metrics` lists only the caller's tenant manifest.
8. `ISemanticCatalogService` loses its tenant-less members (internal API; all in-repo callers updated).
9. New startup validation for `Semantic:*` and `GraphQL:Aggregation:*`.
10. Docs: F-DATA-08 section 4.2, F-DBT-07 section 4.3, F-GOV-19 line 48 and the diagram in F-DATA-08 are outdated after this change (Phase 6).

## 11. Security Notes for Phase 3 (review focus)

1. **Routing change (A-5.1, F-1):** confirm that the planner path applies the tenant predicate, row filters and masks exactly like the executor path for the aggregate (`PlannedTableRead: true` request) and that no caller can reach the executor branch for a SQL table when a SQL service exists.
2. **Differencing:** k-anonymity does not stop filter-based differencing (T-2.6). Decide whether a per-user query-budget or a minimum filter selectivity is required beyond DP noise; confirm `suppressedRowsCount` gating (F-9, A-4) and whether `suppressedGroupsCount` should be exposed at all for GraphQL.
3. **Ordering and limit after suppression:** verify T-2.4/T-2.5 against `GovernedAggregationService.cs:211-284`; note that DP noise is applied after ordering and limit (`:286-303`), so ordering reflects true values.
4. **MIN/MAX/COUNT_DISTINCT:** only exposed for groups that survive suppression; the merged `OTHER` row can contain `MIN`/`MAX` of small groups combined (still >= k rows together); review whether `MIN`/`MAX` on merged rows is acceptable.
5. **Existence and column oracle (SI-112-2):** uniform `AGGREGATION_COLUMN_UNAVAILABLE`; check timing (validation before any query), audit text, `extensions`, and that masked columns are intentionally distinguishable.
6. **Typed filter builder (SI-112-1):** no raw text reaches the compiler; `LIKE` escaping, IN-list limits (`MaxInListSize`), depth limit, parameter naming collisions with the pipeline's own `@rf*`/`@gq*` parameters (`TreeSqlCompiler.cs:148,179` rename scheme), no literal in `SqlPredicate`.
7. **Noisy-result cache (F-5):** key completeness (tenant, user, table, group columns, aggregates, canonical parameters, order, limit, k, strategy, day) and memory bound (`CacheMaxEntries`).
8. **Tenant isolation of the manifest (F-6, SI-112-5/6):** exact-tenant lookups only, no legacy fallback, import tenant from the validated request tenant (`EndpointSecurity.GetRequestTenant`), `GET /dbt/metrics` information exposure (any authenticated user lists the tenant's metric names; consider the MCP "unauthorized metrics are filtered" rule), metric filter templates are admin-authored SQL text now persisted across restarts (import-time parse check, heuristic column extraction in `CombineMetricFiltersWithWhere`), ingestion upserts virtual tables into the global catalog (`semantic.semantic.<model>`) regardless of tenant.
9. **Read-only tokens:** `ReadOnlyOperationMiddleware` rejects only mutation documents; confirm that no query field now reachable by read-only tokens writes state (the aggregate and `queryMetrics` fields write audit and DP budget entries only), and that DP budget consumption by read-only tokens is acceptable (it is per user SID).
10. **Cost and amplification:** root-field alias limit (`MaxRootFieldsPerOperation`, default 10) multiplies aggregate cost; confirm the cost rule counts every alias; `MaxGroups` x `MaxAggregates` response size is bounded by `GraphQL:MaxResponseBytes`.
11. **Error handling:** fixed messages, no column or value echo, `extensions.code` set; the unhandled `ArgumentException`/`KeyNotFoundException` paths of the old resolver are gone.
