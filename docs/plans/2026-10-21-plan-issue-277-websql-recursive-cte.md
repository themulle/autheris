## 1. Verified code facts (beyond the PRD)

1. `SqlQueryAnalyzer.ExitNamedQuery` (line 180) is the only place a CTE name enters `_cteScopeStack`; `EnterQuery` (122) copies the parent scope, so a name added in `EnterNamedQuery` is visible in the CTE body.
2. `CompileCacheKey.Material` (`Ast/Emit/CompiledSqlTemplate.cs:258`) serializes every public property of `CompileRequest` by reflection. New request properties enter the template key automatically.
3. The root row cap is already emitted on every dialect (`AstSecurityVisitor.Select.cs:90-101`, clamp of `EnforcedMaxRows`).
4. The Trino grammar has no `OPTION (...)` clause: a user query hint is a syntax error (400 `SQL_SYNTAX_ERROR`) before compile.
5. Keyword-less self-reference is rejected at compile time (CR-ADG-32, `AstSecurityVisitor.Tables.cs:28-30`) as a plain `SecurityException` (403 `SQL_POLICY_VIOLATION`); the router answers earlier with 403 `SQL_POLICY_DENIED` because the analyzer records the name as a table.
6. Provider errors are mapped in `DmlErrorSanitizer.Map` (`Ast/Emit/DmlConstraintViolationException.cs:62`), called by `GovernedSqlExecutor.SanitizeProviderError`. Timeouts are classified first (`DataAccessErrorClassifier`, SQL Server -2, PG 57014, SQLite interrupt guard -> `TimeoutException`).
7. `CrossSourceQueryRouter` (line 132) decides `isCrossSource`; the single-source path compiles the whole statement via `GovernedSqlRewriter` -> `CompileRequestFactory.Create`. `SubtreeCompiler` also uses `CompileRequestFactory.Create` (line 226). `SubtreeCompiler:159` and `FederatedDuckDbExecutionService:461/486` deny only resolved member tables; they need no change once the analyzer no longer emits the self-reference.
8. MCP `query_sql` resolves targets through `McpDataTargetResolver` (`ReferencedTables`, table-less -> `SqlNoTable`); the analyzer fix covers it.

## 2. Design decisions

1. **D-1 Analyzer scope timing (FR-1).** `SqlQueryAnalyzer.EnterNamedQuery`: when the parent `WithContext` has `RECURSIVE()`, add the folded CTE key to `_cteScopeStack.Peek()` before the body; `ExitNamedQuery` stays (idempotent add). Non-recursive WITH keeps Exit-timing. Set `SqlQueryMetadata.HasRecursiveCte` (new `init` property, default `false`, no positional change).
2. **D-2 Keyword-less self-reference (FR-8 input half: declined, default taken).** Input is Trino SQL, where a self-reference in a non-recursive CTE names the outer table; promoting it would change name resolution and reopen CR-ADG-32. The analyzer tracks a `_definingNonRecursive` stack (push in `EnterNamedQuery`, pop in `ExitNamedQuery`); `RecordTableAccess` still records the name (no change for other analyzer consumers) and sets `SqlQueryMetadata.HasNonRecursiveSelfReference`. `CrossSourceQueryRouter` checks the flag before any table lookup and throws `SqlCompileNotSupportedException(Construct)` (422 `SQL_CONSTRUCT_NOT_SUPPORTED`). `AstSecurityVisitor.Tables.cs:30` throws the same type. The answer is catalog-independent (no existence oracle, SEC-X1-05). Output half of FR-8 already holds (`RecursiveKeyword_IsEmittedPerDialect`).
3. **D-3 Opt-in gate (FR-4, D4 kept).** `CompileRequest.AllowRecursiveCte` (default `false`) -> `AstSecurityVisitorOptions.AllowRecursiveCte`. `AstSecurityVisitor.Select.cs:39`: `With.IsRecursive && !AllowRecursiveCte` -> `SqlCompileNotSupportedException(Construct)`; a recursive WITH in a DML statement is rejected the same way regardless of the switch (read-only scope, default taken). Gate in the compiler covers single-source, subtree and MCP paths.
4. **D-4 Runaway bound (FR-5..FR-7, D3 confirmed).** Dialect-neutral options were evaluated and rejected: (a) an injected depth column changes `UNION` dedup (cycles no longer terminate, duplicates after projection), the CTE column list seen by `SELECT *`, and Oracle column-list rules; (b) the outer `LIMIT cap` already exists (fact 3) and stops streaming plans early on PostgreSQL/SQLite/SQL Server, but any blocking operator (aggregate, `ORDER BY`, `DISTINCT`, hash join) defeats it, so it is documented as best-effort, never as the bound. Chosen bounds: SQL Server emits `OPTION (MAXRECURSION n)` (n = `MaxRecursionDepth`, never 0) -> error 530 -> `SQL_LIMIT_EXCEEDED`; Oracle native cycle detection ORA-32044 -> `SQL_LIMIT_EXCEEDED`; everything else, and all non-cyclic runaways on PG/Oracle/SQLite, end at `ExecutionTimeoutSeconds` -> `SQL_TIMEOUT` (504; SQLite via `SqliteExecutionGuard`). Fail-closed: no result is returned before the provider error.
5. **D-5 MAXRECURSION emission.** `SqlEmitterContext` gets `MaxRecursionDepth` (int) and `RecursiveWithEmitted` (set in `GenerateWithClause` when `IsRecursive`). `SqlServerDialectGenerator` overrides `GenerateSql`: after the base call, if `RecursiveWithEmitted`, append ` OPTION (MAXRECURSION n)` with an invariant-culture integer literal. `SqlDialectGeneratorBase.Generate` (internal overload) takes `maxRecursionDepth`; `GovernedSqlCompiler` passes `request.MaxRecursionDepth`. If `EmittedSqlInvariantChecker` rejects the suffix, allow exactly this tail form there.
6. **D-6 Limits validation.** `CompileLimits.Normalize`: `AllowRecursiveCte && MaxRecursionDepth is < 1 or > 10000` -> `SqlCompileConfigurationException` (500, fail closed). `GatewayCoreOptionsValidator`: `Gateway:WebSql:MaxRecursionDepth` outside 1..10000 fails start (FR-11). Defaults: `AllowRecursiveCte=false`, `MaxRecursionDepth=100` (D1, D3, D6).
7. **D-7 Template cache key.** Both properties live on `CompileRequest` (fact 2), so the key changes with them; asserted by test, no key code change. `CompiledSql.HasRecursiveCte` (init) is carried through `CompiledSqlTemplate.From/Rebind` so a cache hit keeps the audit flag.
8. **D-8 Cross-source (FR-9, D5).** `CrossSourceQueryRouter`: `metadata.HasRecursiveCte && isCrossSource` -> `SqlCompileNotSupportedException(Construct)` before planning or staging. OLAP/DuckDB keeps rejecting `RECURSIVE` (D2, unchanged).
9. **D-9 Provider error mapping.** `DmlErrorSanitizer.Map`: new row before the data-error row: SQL Server `Number == 530`, Oracle `Number == 32044` -> `GovernedSqlException(LimitExceeded, dialect)` (fixed message, no driver text).
10. **D-10 Audit and startup (FR-10, FR-11).** `GovernedSqlExecutor` success audit (`AddCompilerAudit`, ~line 811) writes `recursiveCte=true` only when `compiled.HasRecursiveCte`. `GatewayStartupValidator.ValidateStartup` logs one warning when `AllowRecursiveCte=true` (with the depth and timeout values).
11. **D-11 PR #278 overlap.** No change to `WebSqlStatementManager.cs`, `TrinoMetadataQueryHandler.cs` or `.github/workflows/*`.

## 6. Phase 3 security review (csharp-security-expert, 2026-10-21)

**Verdict: APPROVED WITH CONDITIONS.** Verified: masks, tenant filter and row policy are applied at the table scan (`AstSecurityVisitor.Tables.cs` `SecureTyped`: mask expression in the inner projection), so values fed through recursion or aggregated over it are already masked/filtered; the typed catalog holds only analyzer-reported, authorized tables, so a compiler/analyzer disagreement "analyzer says CTE, compiler says table" ends in "could not be resolved" (deny). The compile-time catalog check (`EnsureRecursiveCteIsNotACatalogTable`) therefore only fires for names the caller was already authorized for and that were reported elsewhere; after D-1 a recursive name equal to an unreferenced table is accepted as a pure CTE (no physical read, emitted as delimited scope key). This is acceptable and avoids a table-existence oracle, but it is a behaviour change (SEC-277-02).

### Binding conditions
- SEC-277-01 Scope parity (fail-closed). The analyzer adds a name on `EnterNamedQuery` only for a `WITH` whose parse node has `RECURSIVE`, per CTE in order (no forward visibility), with the same `FoldIdentifierForScope` key and ordinal comparison as the compiler. Any analyzer/compiler difference must deny. The compiler stays the authority; no analyzer result may relax a compiler check.
- SEC-277-02 Shadowing. `EnsureRecursiveCteIsNotACatalogTable` stays and consults only the request catalog (never the repository), with a fixed message that names no table or schema. Nested WITH, `ORDERS`/`"orders"`/`"ORDERS"` variants, forward/mutual reference to a later CTE named like an authorized table, and a name equal to a table referenced in a sibling scope stay rejected. The accepted-as-CTE case (name equals an unreferenced table) must return exactly the response of a nonexistent name. Document the behaviour change in the plan and the feature doc.
- SEC-277-03 Gate order. The `AllowRecursiveCte` check runs first in `VisitSelect` (before `EnsureRecursiveCteIsNotACatalogTable`) and in the router (`HasRecursiveCte && !Allow` -> 422 before table lookups). Recursive WITH in INSERT/UPDATE/DELETE/MERGE/CTAS is rejected independent of the flag. `AstSecurityVisitorOptions`, `CompileRequest` and `CompileLimits` default to disabled; no hook in `CompilerHooks` may disable the gate.
- SEC-277-04 Keyword-less self-reference. The flag check (`HasNonRecursiveSelfReference`, 422, fixed message) runs on every path that consumes `ReferencedTables` for authorization or lookup before any existence-dependent answer: `CrossSourceQueryRouter`, `McpDataTargetResolver`/MCP `query_sql`, `GovernedSqlRewriter`. Response identical whether the name is an existing, forbidden or unknown table. The compiler throws the same type as defense in depth.
- SEC-277-05 MAXRECURSION. The invariant checker allows exactly one tail ` OPTION (MAXRECURSION n)`, only on SQL Server, only when `RecursiveWithEmitted`, as final text, with n equal to the validated `MaxRecursionDepth` (1..10000, from options, never from SQL text). Any other `OPTION`/hint text, a second tail or a different n fails the invariant. A user hint stays a Trino syntax error. `CompileLimits` out of range with the flag on is a 500 configuration error.
- SEC-277-06 Error mapping. SQL Server 530 and Oracle 32044 map to a fixed message (check the first error and `Errors` collection; no driver text, SQL, table or column names in response, audit or log message). Timeout classification precedes the new row. Fail-closed: no rows are sent before a provider error.
- SEC-277-07 DoS bounds. Depth is not a work bound (fan-out); the timeout is. With `AllowRecursiveCte=true`, `GatewayCoreOptionsValidator` fails start unless `ExecutionTimeoutSeconds` is 1..300. Recursive and tableless recursive statements use the same concurrency/rate limits, row cap and timeout as every WebSQL statement, with no bypass path.
- SEC-277-08 Q-2 resolution. No in-code temp-space bound in this lane. Docs section 7/10 state a deployment prerequisite when the flag is on (PostgreSQL `temp_file_limit`/`work_mem` on the gateway role, Oracle temp tablespace quota/profile, SQL Server tempdb limits) and the startup warning names it. The flag stays default `false`; it is never auto-enabled by any profile or test default.
- SEC-277-09 Audit. `recursiveCte=true` is written on success, failure, timeout, limit-exceeded and rejected (DML) audits, not only success; no raw SQL unless `StoreCompiledSql`; the cache hit keeps the flag.
- SEC-277-10 Mask guards on recursion. For a recursive CTE the masked-output set (`CollectMaskedOutputColumns`) is computed with the CTE name already in scope (self-reference inherits) and covers every member (anchor and recursive) conservatively: a masked column in any member marks the CTE output column at that position, or, if positions cannot be resolved, all output columns. Predicate/aggregate/ORDER BY guards then behave as for a non-recursive CTE.
- SEC-277-11 Surface containment. The flag is read only by the governed WebSQL/MCP compile path. Virtual-filter fragments, row-policy predicates, stored endpoints/procedures and every `new CompileRequest` outside `CompileRequestFactory` keep `AllowRecursiveCte=false`. The developer lists in the PR every caller of `GovernedSqlRewriter` and states which inherit the flag (Arrow export, stored endpoints) and why that is acceptable, or sets them to false.
- SEC-277-12 Cross-source. The router rejects `HasRecursiveCte && isCrossSource` (including HTTP-declarative sources) before any provider call, planning or staging; DuckDB OLAP keeps rejecting `RECURSIVE`.

## 7. Changelog

- 2026-10-22 (WP-1, Phase 4): plan facts re-verified against `91821d57`; drift and implementation notes:
  - `INSERT ... WITH ...` is refused earlier by the AST builder (`AstBuildException`, "WITH, ORDER BY or LIMIT on an INSERT source"); UPDATE, DELETE and MERGE reach the compiler gate (`SqlCompileNotSupportedException(Construct)`, checked on the built AST before the security visitor). Both reject independent of `AllowRecursiveCte`.
  - The DML gate is a pre-pass in `GovernedSqlCompiler` (`ContainsRecursiveWith`), not a visitor flag; the opt-in gate for SELECT is the first check of `AstSecurityVisitor.VisitSelectStatement` (SEC-277-03).
  - SEC-277-05: the tail is a new `EmittedRangeKind.RecursionOptionTail`; `EmittedSqlInvariantChecker.Check` takes `maxRecursionDepth` and additionally rejects any unregistered `OPTION`/`MAXRECURSION` token (all dialects). `OPTION (RECOMPILE)` after a table parses as an alias with a column list (not a hint) and is emitted delimited.
  - SEC-277-10: the masked-output set of a recursive CTE is a fixed point over all members, mapped by output position (new `AstSecurityVisitor.RecursiveCte.cs`); unresolvable positions reject (fail closed).
  - `SqlCompileConfigurationException` gained an internal fixed-message constructor (depth out of range).
  - Existing recursive tests in `tests/TrinoSqlEngine.Tests` (conformance runner, gate harness, mask-guard and typed-guard suites) and the four `AstCompiler*ExecutionTests` request builders set `AllowRecursiveCte = true`; the SQL Server conformance fixture `cte-006` now ends with `OPTION (MAXRECURSION 100)`.
