## 1. Goal and outcome
Every data-access decision (read, insert, update, delete, execute, discover) in Autheris is made by one component, `IAccessDecisionPoint`, from one grant model: approved, time-limited grant records in the grant store (consent requests, access-profile assignments materialized per OD-32, owner grants per OD-34) for users and AD groups, with the precedence explicit deny > grant > default deny. Measurable: (a) zero `new TableAccessPolicy(` outside `Application/Policy/Pdp/`; (b) zero references to `IRebacEvaluator`, `IRebacStore`, `RebacTableGate` in `src` and no `IPolicyEnforcementService` consumer on the data path (only the interface, `CasbinEnforcementService` and its registration remain, deleted by WP-SIMPL-14); (c) the cross-transport parity matrix (section 6.3) passes with identical outcomes on all transports and sources; (d) `POST /api/v1/authz/explain` answers "why can X see Y" with a complete, ordered trace; (e) no role grants or bypasses data access; (f) every allow decision lists all contributing grant ids (OD-42).

   - `Precondition`: identity incomplete or tenant mismatch, `IsRoleResolutionDegraded` (keep GOV-08), group resolution `Degraded`, object inactive, transport not allowed for the source (existing transport gate), write operation on a transport without write wiring (OD-35, `WRITE_TRANSPORT_NOT_WIRED`) -> deny.

PII columns are `Masked` unless a `Clear` rule exists. Row predicate = OR over the granting records' row scopes (an unfiltered grant contributes TRUE), then AND every hard row policy of the user or an effective group (subject-bound, OD-39); from WP-SIMPL-48 PR 3 on, `RowScopeCompiler` builds this predicate. Caller attributes are bound only here; unresolved -> deny with `ATTR_UNRESOLVED`. The contributing records fill `Grants` (step 1).

## Decisions taken in this spec
- D-46a: Service principals are matched as users (non-human users); OD-22 "user" includes them.
- D-46b (OD-32): A profile never grants by itself; only its materialized, approved grant records do. An access profile is a request template; its assignment to a user or AD group runs the approval path of WP-SIMPL-47 and materializes one time-limited grant record per profile item, object or pattern, matched at decision time (OD-40; operation, column set with Clear/Masked per PII column, row scope). Masking level and row scope are attributes of those records (SR-M-07 masking-modifier semantics removed). Roles are no assignees; break-glass assignments do not exist. Explicit deny beats every grant record.
- D-46c (OD-39): Row scopes are ORed across grants (a filtered and an unfiltered grant of the same subject yield all rows, by intent) and ANDed with the subject's hard row policies; narrowing filters are ANDed after that. Column state per cell when grants differ (OD-41).
- D-46d (OD-31): Schema contracts, restricted scopes and auth hooks are narrowing inputs at the `Narrowing` step after the grant union (deny or extra row filter only). Plugin `EnrichRolesAsync` output is control-plane only and never joins the group set used for grants or denies.
- D-46e: `TableAccessDecision` is extended instead of introducing a new decision record, to limit consumer churn.
- D-46f: ReBAC tuples are not migrated into grants; a one-shot report lists them as candidates for owner-approved requests.
- D-46g (OD-33): A write decision never requires a read allow; its grant step is the write-grant evaluation; explicit deny and preconditions still apply. `OwnRows` updates use the caller's RLS predicate from the PDP.
- D-46h (OD-34): Owners have no implicit access; they read through owner grant records, which the PDP treats like any other grant record (source kind `Owner`).
- D-46i (OD-42, revises R6): The decision record carries every contributing grant id; there is no single authorizing grant; WP-SIMPL-42 and the data-access audit use the full list.
- D-46j: Delegated sources (Databricks OBO) are decided by the PDP first; source permissions only narrow further.
- D-46k (OD-35): Transports without write wiring deny writes in the `Precondition` step, so wiring a transport later needs no new decision logic.
