## 1. Goal and outcome
Replace the FinOps cost accounting (`Application/FinOps`, `FinOpsBudgetMiddleware`, `/api/v1/finops/*`, `Gateway:FinOps`) with a core usage-accounting capability built on the existing consumer usage recorder. Every authenticated call on every transport is metered with **neutral measures** (requests, governed queries, rows, response bytes, duration, source compute time and source-reported cost where the source provides them, GraphQL analysis cost, outcome incl. denies) per transport, table or stored procedure, **data source**, application/client id and **grant** (authorizing grant id with `valid_from`/`valid_until` from the WP-SIMPL-46 decision record; grant records per WP-SIMPL-47), attributed to the canonical user SID and the caller's AD group SIDs, stored as daily aggregates in the governance DB. **Cost units** are derived from the neutral measures by a per-data-source **tariff** (base fee per query, per row, per MiB, per compute second, pass-through of source-reported cost, or any linear combination); tariffs are versioned, immutable and valid for date ranges, so a historic report is reproducible after tariffs change (OD-29). Reports per user, AD group, tenant, data source, table, application and grant show measures and cost units, with CSV/JSON export and audited reads. Measurable: (a) one transport-coverage integration test per transport finds exactly the expected aggregate row incl. data source and grant id; (b) a governance DB outage never fails or slows a data request (test); (c) `git grep -i finops -- src deploy` is empty; (d) per-group reports multi-count members and billing-group reports sum exactly to the tenant total (contract tests); (e) a report for a past range returns identical cost units before and after a new tariff version is added (test). Optional sub-package 42-Q adds quotas per user/group/tenant on the same counters.

## 5. Implementation steps (TDD order)

### 5.1 Model and attribution rules (PR-1)
1. **Types** in `src/Autheris.Application/Usage/`:
   ```csharp
   public enum UsageOutcome : byte { Allow, DenyAccess, DenyRateLimit, DenyCost, DenyQuota, DenyOther, Error }
   public readonly record struct GrantRef(string GrantId, DateTimeOffset? ValidFrom, DateTimeOffset? ValidUntil)
   { public static readonly GrantRef None = new("", null, null); }   // only before WP-SIMPL-46 PR 1 and on deny facts; mapped from TableAccessDecision.AuthorizingGrant
   public readonly record struct SourceExecutionStats(long? SourceComputeMs, decimal? SourceCost, string? SourceCostUnit, string? SourceQueryId);
   public readonly record struct UsageFact(TableIdentifier Table, string DataSource, UsageOutcome Outcome, long Rows, bool RowsMeasured,
       long AnalysisCost, GrantRef Grant, SourceExecutionStats Source);
   public sealed record UsageIdentity(TenantId Tenant, Sid UserSid, IReadOnlySet<Sid> GroupSids);
   public interface IUsageRecorder { void Record(in UsageFact fact, TenantId tenant, Sid actor); } // never throws, never awaits
   ```
   `Table` is the table identifier, or for a stored-procedure execution the procedure identifier (domain.schema.procedure). `DataSource` = `Table.SourceName` of the resolved table metadata, or the procedure's connection for procedures (`""` when unresolved, e.g. a deny before metadata lookup). `AnalysisCost` = the existing GraphQL/table-stream cost value (a neutral measure, not a cost unit). Delete `IConsumerUsageRecorder`/`ConsumerOutcome` in PR-3 after the call sites move (`ConsumerOutcome` maps 1:1, plus `DenyQuota`, `Error`).
2. **Request scope** `UsageRequestScope` (sealed class, ambient via `static AsyncLocal<UsageRequestScope?> Current`; no DI lifetime coupling with singleton services). `static UsageRequestScope Begin(UsageIdentity, DataSourceTransportFlags transport, CallerContext? caller)` returns an `IDisposable` handle; `AddFact(in UsageFact)` (lock-free append to a small array, cap 64 facts per request, excess merged into the last fact of the same table); `Complete(long durationMs, long bytes, int statusCode)` emits to `IUsageAggregator` exactly once (second call no-op).
3. **Recorder** `UsageRecorder : IUsageRecorder` (singleton): if `UsageRequestScope.Current` is active and its tenant/user equal the arguments, `AddFact`; otherwise emit a standalone event with transport `None`, empty group set, and increment metric `autheris_usage_unscoped_total`. Wrap everything in `try/catch` -> increment `autheris_usage_record_errors_total`; never rethrow.
4. **Attribution rules** (pure static `UsageAttribution`, unit-tested):
   - User key: canonical `SecurityPrincipalContext.UserSid.Value` (D-42a). With `PseudonymizeUsers = true`: `"h:" + hex(HMACSHA256(key, sid))[..32]`, key only from `PseudonymizationKeyVaultRef`; missing key -> startup validation error (no default, no random fallback).
   - Groups: `SecurityPrincipalContext.GroupSids` only (never raw headers or request parameters). Remove SIDs matching `ExcludedGroupSidPrefixes` (default: `S-1-1-`, `S-1-2-`, `S-1-3-`, `S-1-5-32-`, `S-1-5-11`, `S-1-5-2`, `S-1-5-4`, `S-1-5-15`, `S-1-5-64-`, `S-1-16-`, `S-1-18-`); if `IncludedGroupSidPrefixes` is non-empty keep only matches. Sort ordinal; keep the first `MaxGroupsPerUser` (default 256) and count truncations in `autheris_usage_groups_truncated_total`.
   - Group set id: first 32 lowercase hex chars of SHA-256 over the sorted SIDs joined with `\n`; empty set -> `"none"`. Order-independent.
   - Billing group (optional, D-42c): `BillingGroups[tenant]` is an ordered list of group SIDs; the first configured SID contained in the user's set wins, else `"unassigned"`. Exactly one per request, so billing reports partition the tenant total.
   - Multi-counted semantics (D-42b): the per-group report counts a request once for every group in the caller's set; group totals therefore do not sum to the tenant total. Every group-report payload carries `"multiCounted": true` and the tenant total; CSV header comment line `# multi-counted: a user in N groups is counted in each group`.
   - Request-level metrics (requests=1, durationMs, bytes) are attributed to the first fact's table and data source (the root table; `GovernedTreeQueryService` records the root first), or to table/data source `""` when the request has no fact. Every fact increments `queries`, `rows`, `analysisCost`, source stats and its outcome counter.
   - Grant (OD-29, R6): an Allow fact carries the `GrantRef` mapped from `TableAccessDecision.AuthorizingGrant` of the WP-SIMPL-46 decision that allowed it (never derived from request input). Every allow has a grant record: data owners are counted under their owner grant id (OD-34), materialized access-profile grants under their own record id; there are no `basis:*` ids (no role, owner, public or break-glass access path exists, ADR-020). An Allow fact without a grant id (a defect) is recorded with `grant_id = "invalid"` and increments `autheris_usage_allow_without_grant_total`. Deny facts carry `""`. The grant id is a series-key dimension, so every counted access is tied to exactly one grant per day; `valid_from`/`valid_until` are stored once per grant id in `USAGE_GRANT_REF`. Outcome without facts from the status code: 2xx/3xx Allow, 403 DenyAccess, 429 DenyRateLimit (DenyQuota when the problem code is `USAGE_QUOTA_EXCEEDED`), other 4xx DenyOther, 5xx Error.
5. **Aggregator** `UsageAggregator : IUsageAggregator` (singleton, Application layer, no I/O). Key `UsageSeriesKey(TenantId, DateOnly DayUtc, string UserKey, string GroupSetId, string BillingGroup, DataSourceTransportFlags Transport, string Application, string ClientId, string DataSource, string TableId, string GrantId)`; application/client id via the existing `CallerLabelNormalizer` (64-char caps). Counters (all `long`, `Interlocked`): `Requests, Queries, Rows, RowsMeasured, Bytes, DurationMs, AnalysisCost, SourceComputeMs, SourceComputeMeasured, SourceCostMicros, SourceCostMeasured, Allow, DenyAccess, DenyRateLimit, DenyCost, DenyQuota, DenyOther, Errors` (`SourceCostMicros` = source-reported cost x 1,000,000, rounded; the source cost unit is fixed per data source by the tariff, a fact whose `SourceCostUnit` differs from the tariff's is counted in `autheris_usage_source_unit_mismatch_total` and not added). Cost units are not stored; they are derived at report time from the neutral measures and the tariff version valid on each day (step 9b), which keeps history reproducible. Grant refs are kept in a side map `(tenant, grantId) -> (validFrom, validUntil)` like group sets. Double-buffered generations: `Swap()` does `Interlocked.Exchange` of the generation, then waits (SpinWait, max 100 ms) until the old generation's `ActiveWriters` counter is 0. Capacity `MaxSeries` (default 100,000): a new key beyond capacity is folded into the same user's key with `TableId = "*other*"`, `Application = "*other*"`, `ClientId = ""` (keeping `DataSource` and `GrantId`, so pricing and per-grant totals stay correct) (counts are never dropped silently; metric `autheris_usage_series_overflow_total`); only if that key is also new and capacity +1% is exceeded the event is dropped and `autheris_usage_dropped_total` incremented. Group sets are kept in a side map `(tenant, groupSetId) -> Sid[]`, flushed with the generation.
6. **Options** `src/Autheris.Domain/Options/UsageAccountingOptions.cs`, section `Gateway:UsageAccounting` (`GatewaySections.UsageAccounting`), `ValidateDataAnnotations().ValidateOnStart()` plus validator: `FlushIntervalSeconds` 15 [5..300]; `MaxSeries` 100_000 [1_000..1_000_000]; `RetentionDays` 400 [30..1100]; `MaxFlushRetries` 20 [1..1000]; `ExcludedGroupSidPrefixes`, `IncludedGroupSidPrefixes` (each must start with `S-1-`); `MaxGroupsPerUser` 256 [1..4096]; `BillingGroups : Dictionary<string, List<string>>` (keys must be known tenants or `*`, values valid SIDs, no duplicates); `GroupDisplayNames : Dictionary<string,string>` (SID -> name, name <= 256 chars); `PseudonymizeUsers` false; `PseudonymizationKeyVaultRef`; `MaxReportRangeDays` 366 [1..1100]; `MaxReportRows` 50_000; `DataOwnersSeeUsers` true. No `Enabled` switch (OD-20: usage is always tracked; D-42d).

### 5.2b Tariffs and cost units (PR-4a, OD-29)
9b. **Tariff model** `UsageTariffVersion` (Application/Usage) with the columns of `USAGE_TARIFF`. Cost units of one aggregate row on day `d` for data source `s` and tenant `t`, using the tariff version valid on `d` (lookup order: `(t, s)`, `(t, *)`, `(*, s)`, `(*, *)`; `valid_from <= d < valid_until`):
   ```
   computeSeconds = (compute_basis == 0 && source_compute_measured == queries) ? source_compute_ms / 1000m : duration_ms / 1000m
   costUnits = base_per_query * queries + per_row * rows_returned + per_mib * bytes / 1_048_576m
             + per_compute_second * computeSeconds + per_analysis_cost * analysis_cost
             + source_cost_factor * source_cost_micros / 1_000_000m
   ```
   Every model of OD-29 is a parameter choice: per-query fee (`base_per_query`), per row and/or per byte (`per_row`, `per_mib`), per compute second (`per_compute_second`, e.g. a Databricks warehouse's DBU rate x price), pass-through (`source_cost_factor = 1`, `source_cost_unit = "DBU"`), or any combination. The formula is linear, so applying it per (day, data source) aggregate equals applying it per query; reports therefore group internally by the requested dimensions plus `(day, data_source)`, apply the tariff, then roll up in C# with `decimal` (rounded to 6 decimals only at output). No tariff found -> cost units `0` and the row carries `tariffMissing: true`. Only rows with a non-empty `grant_id` (allowed governed reads and procedure executions) are priced; deny facts and requests without a data access carry `grant_id = ""` and cost 0 (D-42m), but their measures are still reported.
   - **Versioning rules** (`UsageTariffService.AddVersionAsync`): versions are immutable; a new version must have `valid_from >= today UTC + 1 day` (no retroactive change, history stays reproducible, D-42k); the previous open version is closed at the new `valid_from`; gaps are allowed (gap = no tariff). Validation: all rates `>= 0` and `<= 1e9`, at least one rate `> 0`, `source_cost_unit` required iff `source_cost_factor > 0` and must equal the unit the data source's collector reports, `unit_label` `^[A-Za-z0-9 _.-]{1,32}$`, `reason` required.
   - **Tariff API** in `UsageEndpoints.cs`: `GET /api/v1/usage/tariffs?dataSource=&at=` (UsageAdmin; tenant rows + inherited `*` rows), `GET /api/v1/usage/tariffs/{dataSource}/versions` (UsageAdmin), `POST /api/v1/usage/tariffs/{dataSource}/versions` (tenant tariffs: TenantAdmin; `*` tenant or `*` data source: ClusterAdmin only). Every POST writes `IAuditWriter.RecordRequiredAsync` event `UsageTariffVersionAdded` (old and new version, caller, reason) before commit; audit failure -> 503, no write. No PUT/DELETE routes exist (405 test).
   - **Initial tariffs** may be seeded from options `Gateway:UsageAccounting:InitialTariffs` (list with the same fields, `valid_from` any date) only when `USAGE_TARIFF` holds no row for that `(tenant, data_source)`; afterwards the option is ignored with a startup warning (D-42l). Unknown `data_source` names (not a configured source) fail validation.

## Decisions taken in this spec
- D-42a: Usage rows store the canonical user SID (OD-20 requires per-user tracking); pseudonymization is an opt-in mode with a mandatory vault key. This supersedes the HMAC-only actor sample and removes `CONSUMER_APP_ACTOR_DAILY`.
- D-42b: Per-group reports are multi-counted by design (a user in N groups counts in each); exact partition is offered only through the optional ordered billing-group mapping.
- D-42c: Billing group = first configured group in the caller's set (deterministic, config order), else `unassigned`.
- D-42d: No `Enabled` switch: usage accounting is always on (OD-20); volume is bounded by series caps, not by disabling.
- D-42e: No FOCUS export in this WP: tariffs yield cost units with a label, not billed currency amounts; CSV/JSON only. A FOCUS mapping can be added later on top of the cost-unit reports if the owner asks.
- D-42f: Group names resolved at report time from the option map and the SCIM group `objectSid` (WP-SIMPL-43); never by `externalId` or display name; no LDAP calls.
- D-42g: Old consumer daily/actor tables are dropped without data migration (no production deployment; forward-only step).
- D-42h: GraphQL subscriptions are metered at connect; per-event metering is out of scope.
- D-42j (OD-29): Aggregates store only neutral measures; cost units are computed at report time from versioned tariffs. The tariff formula is linear so aggregate pricing equals per-query pricing.
- D-42k: Tariff versions are immutable and only future-dated (`valid_from >= tomorrow UTC`); corrections are a new version, never a retroactive edit, so a past report is reproducible.
- D-42l: Tariffs live in the governance DB with an audited admin API; options only seed an empty table (tariffs must change at runtime without redeploy, and the history must survive config edits).
- D-42m: Only allowed data accesses (non-empty grant id) are priced; denies cost 0 but are reported as measures.
- D-42n: Databricks source cost = query-history compute time; per-statement DBU pass-through only if the API in use exposes it (verify in PR-7), else DBU pricing via `per_compute_second`.
- D-42o (OD-29, OD-34, R6): Per-access grant proof comes from the hash-chained data-access audit entry (new grant fields); usage aggregates give per-grant daily totals. Every allowed access has a grant record (owners via their owner grant); the grant id comes from the WP-SIMPL-46 decision record; no `basis:*` ids.
- D-42p (OD-20/OD-22): stored-procedure executions are metered like table reads (procedure identifier as table key, procedure connection as data source).
- D-42i: Retention default 400 days (aligned with `Audit:Retention:DataAccessDays`), configurable 30..1100; erasure re-keys rows to `erased` to keep aggregates.
