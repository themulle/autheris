## 1. Goal and outcome
Close the findings of both reviews so that the Stage 3 deletions, moves and the module host leave no fail-open path, no forgeable audit record, no dead ownership entry, no leftover secret plumbing and no lost security test coverage. Measurable: every item in section 5 has a Red test (or an architecture test for deletions) that fails on `origin/main` and passes after its PR.

## 2. Preconditions and dependencies
- WP-SIMPL-25 and WP-SIMPL-27 are merged (module host and Lakehouse module exist on `origin/main`).
- PR A is a release blocker. All other PRs are independent of each other and may follow in any order; PR B3 and PR B6 both touch `ErrorSanitizingFilter.cs` (rebase, no logical conflict).
- A1, A4 and A5 are exploitable under preconditions. This public plan and all PR texts state only the fail-closed rule and the fix, never reproduction steps.
- WP-SIMPL-46 later moves the read paths onto `IAccessDecisionPoint`; B15 keeps the decision point correct for every operation so that move needs no further authorization change.

## 9. Decisions and open questions
- D-50a: anti-rollback floor in configuration (`Gateway:Modules:MinVersions`); keyring from embedded keys with `Gateway:Modules:RevokedKeyIds`. Default taken.
- D-50b: native libraries are loaded from a verified private copy, not removed.
- D-50c: the ABAC service is a required constructor dependency (startup fails when missing). The old unknown-IP rule is dropped because no IP rules exist.
- D-50d: aggregation differencing is accepted residual risk (OD-11), mitigated by suppression, `ExposeSuppressedGroupsCount=false` and the `filter_shape` audit field. Default taken.
- D-50e: the ABAC row filter and masking rules apply to every operation (B15).
- D-50f: the module service guard also denies host extension points (startup filters, hosted services, auth options configurators); further additions go through an explicit host allowlist in review.
- D-50g (changed by the code): modules get no governance connection; the "narrow repository" option is dropped because the Lakehouse module does not use the connection (`LakehouseModule.cs:23-28`).
- D-50h (new): C14 deletes the unused module GraphQL extension point instead of hardening it.
- Open question 1 (B14): where the module signing key lives (GitHub environment secret vs. offline/HSM signing in a manual release step). Default taken until answered: protected GitHub environment secret with a required reviewer.
- Open question 2 (C8): whether the culture analyzer rules (CA1304/1305/1307/1310/1311) are enabled too. Default taken: they stay suppressed in this WP.
