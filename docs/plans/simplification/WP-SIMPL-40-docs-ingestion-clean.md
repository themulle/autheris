## 1. Goal and outcome
Docs ingestion (REST `DocIngestionEndpoints`, MCP doc tools, document store, doc search) stays in core and is rebuilt on one replica-safe store: two governance-database tables accessed through the unified `GovernanceRepository` (WP-SIMPL-20). Measurable outcome: (a) every tenant document key contains the tenant id, and no response reveals whether another tenant's document exists; (b) creates are atomic (unique key, no check-then-act); (c) per-tenant quotas (documents, bytes) are enforced in the same transaction as the write; (d) all deposited Markdown passes one sanitiser before storage and is marked untrusted on every MCP/REST read; (e) deposit, replace and delete are audited; (f) `FileSystemUniversalDocStore`, `DocStoreStartupSyncService` and the `/app/shared-docs` volume are deleted. The regression test of GHSA-p234-g3ph-gqh2 (docs ingestion store, owned by WP-SIMPL-36 sub-package 7) stays green through every PR of this WP.

## 3. Scope
### In scope
- Tenant-scoped key space for tenant documents; official (tenant-less) documents in a separate global table; reserved application ids and reserved official keys.
- Atomic create, optimistic replace (`If-Match`), delete with tombstone, per-tenant quota row updated conditionally in the same transaction.
- One authorization policy class used by REST and MCP (OD-9): canonical `ClusterAdmin` writes official docs and global apps; `GovernanceAdmin` writes only its own tenant; null MCP session cannot deposit.
- Size, count and identifier limits as validated options (`Docs` section) with fail-fast validation.
- `UntrustedMarkdownSanitizer` applied on every write path (PUT, bundle, MCP deposit, legacy import).
- In-memory doc search index rebuilt per replica from the database and refreshed by a poller (multi-replica consistency); index keys include the tenant.
- New route `DELETE /api/v1/docs/apps/{appId}/documents/{category}/{docId}` and ClusterAdmin route `DELETE /api/v1/docs/tenants/{tenantId}` (tenant purge).
- Audit attributes for all write routes and the MCP deposit tool; new audit event types for delete, purge and import.
- One-shot legacy import of the existing filesystem layout; deletion of the filesystem store, startup sync service, Docker volume and dead tests.
### Out of scope
- Indexing full document text in `CatalogSearchEngine`. Titles and summaries of linked documents are indexed by WP-SIMPL-41 step 13 (see Decisions 6).
- Embeddings over full document text (WP-SIMPL-41 embeds titles and summaries only); FileSystemWatcher or file-drop ingestion; manifest/YAML/OpenAPI assets in bundles (bundles carry `.md` only, as tenant bundles do today).
- Time-based automatic expiry of documents (retention is explicit delete and tenant purge; Decisions 8).
- `TrustedDocumentAdminEndpoints` (GraphQL trusted documents, unrelated).
- Rewriting `docs/architecture/konzept-data-governance-und-mcp-documentation.md` (reference doc update follows only on owner request).

   ```csharp
   Task<DocWriteOutcome> CreateAsync(DocRecord doc, DocQuota quota, CancellationToken ct);           // Created | Exists | QuotaExceeded | ReservedKey
   Task<DocWriteOutcome> ReplaceAsync(DocRecord doc, long expectedVersion, DocQuota quota, CancellationToken ct); // Replaced | NotFound | VersionMismatch | QuotaExceeded
   Task<DocWriteOutcome> CreateManyAsync(IReadOnlyList<DocRecord> docs, DocQuota quota, CancellationToken ct);   // all-or-nothing (bundle)
   Task<bool> DeleteAsync(DocKey key, CancellationToken ct);                                         // tombstone, usage decremented
   Task<int> PurgeTenantAsync(string tenantId, CancellationToken ct);                                // hard delete + usage row
   Task<DocRecord?> GetAsync(DocKey key, CancellationToken ct);
   ```

   `DocKey(string? TenantId, string AppId, DocCategory Category, string DocId)`; `TenantId == null` addresses the official table, otherwise `TenantScope` requires it (throws `ArgumentException` when empty). Create = one transaction: (1) for tenant docs, `SELECT 1` on the official key: if an official document with that key exists -> `ReservedKey` (official docs are visible to every tenant, so this is no cross-tenant oracle); (2) usage upsert via `dialect.Upsert` then conditional `UPDATE doc_tenant_usage SET document_count = document_count + @n, total_bytes = total_bytes + @b WHERE tenant_id = @t AND document_count + @n <= @maxDocs AND total_bytes + @b <= @maxBytes`; 0 rows -> rollback, `QuotaExceeded`; (3) `INSERT`; `dialect.IsUniqueViolation` -> rollback, `Exists`. A tombstoned row with the same key is revived by `UPDATE ... WHERE deleted_at_utc IS NOT NULL` inside the same transaction. Replace adjusts usage by the byte delta with the same conditional update and `WHERE version = @expected`. All SQL written once (WP-SIMPL-20 rules), executor logs fragment id and duration only (SEC-SIMPL-25), page/batch caps constant (SEC-SIMPL-23).

## 10. Risks, rollback, and things the developer must NOT do
- Risk: index divergence between replicas for up to `IndexRefreshSeconds`; accepted (docs are reference text) and covered by the convergence test. Writes are always consistent (database).
- Risk: sanitiser changes official docs (e.g. inline HTML in runbooks). `Sanitized = true` is returned so authors see it; rule set is deliberately conservative (text is kept, markup dropped).
- Rollback: each PR reverts cleanly; 40c revert restores the filesystem store (40d not yet merged). The migration step is forward-only and additive; leaving the tables after a revert is harmless.
- Do NOT: keep any check-then-act (`Exists` then `Insert`) path; use filesystem paths derived from tenant ids; store provenance inside content; let `GovernanceAdmin` act globally or let a missing tenant default to official (OD-9); log or audit document content or titles; add a feature flag to keep both stores; put advisory details in code, tests, commits or PR text (SEC-SIMPL-01); add an MCP delete tool; index full document text in `CatalogSearchEngine` (titles and summaries only, through WP-SIMPL-41).

## Decisions taken in this spec
1. WP-SIMPL-18 PR F (delete docs ingestion) is removed by OD-18. In WP-SIMPL-18: drop PR F from the PR list, remove the docs files from the inventory, drop test `DocIngestion_routes_return_404`, drop the `src/Autheris.Application/Docs` part of the `test ! -d` check, and do not guard the docs options section; subtract about -2,300 src lines (the 744-line estimate there understated the surface, verified 2,346) and 9 routes from its expected net change. 2. Store: governance database only (two tables plus a usage table through `GovernanceRepository`), no filesystem store, not even for Development. Justification: after OD-1 every environment, including local Development, runs PostgreSQL or SQL Server, so a second implementation would only add a divergent code path; the database gives atomic unique keys, transactional quotas and multi-replica visibility for free; a shared RWX volume (the original concept) cannot provide atomic quota accounting and is unavailable on many clusters.
3. Official vs tenant documents are separate tables, not a nullable tenant column, so the WP-SIMPL-20 `TenantScope` rule (non-null tenant on tenant-scoped statements) holds without exceptions.
4. A tenant may now replace and delete its own documents (with `If-Match`); the old "tenants may only add" rule is dropped.
5. ClusterAdmin writes are always official; ClusterAdmin never writes into a tenant's space and reads only official plus its own request tenant (OD-9 restricts global operations to ClusterAdmin but does not make tenant content globally readable). Tenant purge is the only cross-tenant ClusterAdmin operation.
6. Catalog search (owner addendum, WP-SIMPL-41 step 13 and D10): the dataset search document includes the sanitised titles and summaries of its visible linked documents; full text stays out of `CatalogSearchEngine` and is read through the doc tools, marked untrusted. This WP supplies the store, the sanitiser and the shared rune rules (#500).
7. Delete is REST-only; MCP agents may create and replace but not delete (destructive operations stay with human-driven API clients).
8. Retention = explicit delete, tenant purge, and tombstone purge after `TombstoneRetentionHours`; no age-based expiry (not requested by any issue; can be added later as an option).
9. `MaxDocumentBytes` default lowered from 5 MB (tenant bundle limit today) to 1 MiB: documents are retrieved into LLM context; larger texts are split by the author.
10. Advisory referenced only as "GHSA-p234-g3ph-gqh2 (docs ingestion store)"; owner WP-SIMPL-36 sub-package 7.
