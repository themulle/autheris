## Decisions (default taken)
1. D-20R-1 All four cores fold into `GovernanceRepository` partials as nested types (pattern: `GovernanceRepository.ClassificationAccessSql`); every partial stays < 1,000 lines; after the fold only `AuditSqlCore.cs` matches `*SqlCore.cs`.
2. D-20R-2 Folded SQL becomes subject to SEC-SIMPL-26: constants and bound parameters only. Allowed interpolation (parameter-name suffixes in multi-row `VALUES`/`IN` builders, constant column lists) needs a per-file/member `GovernanceSqlAllowlist` entry with justification; no table name or client text is ever interpolated.
3. D-20R-3 The AD-1 7,000 target is withdrawn (Wave 4-7 aggregates added ~+9,000 by owner-mandated WPs). New acceptance: shrink-only ratchet. Each PR sets `MaxAllowedLoc` to its measured value and may not raise it; a raise needs the `freeze-exception` label (WP-20 decision 4). Expected reductions: WP-52 role-grantee removal, the profile items step ([addendum](WP-SIMPL-52-profile-items-addendum.md)) and this fold. The 6,000 program exit of WP-SIMPL-33 is restated the same way.
4. D-20R-4 Test names stay where they are in `security-tests-base.txt` (for example `WebhookOutboxSqlCoreGoldenTests`) to avoid inventory churn; only references change.
5. D-20R-5 Order: PR A any time; PR B after WP-36 6a (`CdcSubscriptionGovernor`, `CdcWebhookDeliveryService`) merges; WP-29 A2 (move of `Extensions/Cdc` producers) rebases on PR B (no file overlap; `CdcSourceQueries` stays in its allowlist row).
