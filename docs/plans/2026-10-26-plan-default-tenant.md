## 2. Semantics

Terms: D = `Gateway:Tenancy:DefaultTenantId`. Claim = realm binding (explicit realm `Fixed`/`ClaimMapped`) or the standard claim chain (`tenant_id`, `tid`, `tenant`, MS tenantid) for principals without a realm. Implicit realms are `Unbound` (claim ignored, as today). GA = GovernanceAdmin, CA = canonical ClusterAdmin.

| # | D | Claim | Tenant | Scope GA / CA / other | Authenticated endpoint result |
|---|---|---|---|---|---|
| S1 | set | valid | claim (claim wins, D ignored) | Tenant(claim); if claim = D: catalog-owner view / Global / Subject | normal |
| S2 | set | invalid or reserved | none | None | 403 `TENANT_CLAIM_INVALID` (no echo), never D |
| S3 | set | absent (or `Unbound` realm) | D, source `DefaultAssigned` | Tenant(D) = whole catalog (catalog owner) / Global / Subject(D) | normal |
| S4 | unset | valid | claim | Tenant(claim) / Global / Subject | normal |
| S5 | unset | invalid or reserved | none | None | 403 `TENANT_CLAIM_INVALID` |
| S6 | unset | absent | Unresolved | None / Global / None | non-CA: 403 `TENANT_UNRESOLVED` at the middleware gate (fixes the root fallbacks `Sid.GetTenantId`, `TenantResolutionMiddleware:104`, `SecurityContextFactory:124`); CA passes the gate, global admin and catalog work, any tenant-scoped operation without `X-Tenant-ID` gets 403 `TENANT_UNRESOLVED` |
| S7 | any | any | — | — | header `X-Tenant-ID` differing from the tenant: non-CA 403 `CROSS_TENANT_ACCESS_FORBIDDEN`; CA selects (registry lookup only, 403 `TENANT_UNKNOWN`); malformed header 400 `INVALID_TENANT_ID` (unchanged) |
| S8 | any | unauthenticated | none | None | protected endpoints 401 (authorization runs before the gate); `[AllowAnonymous]` endpoints (health, metrics, OpenAPI) 200 and never read the tenant |

Endpoint classes: OData, GraphQL HTTP, WebSQL, MCP HTTP, REST governance, CDC (stream + admin), ReBAC, consent, SCIM all pass `SecurityContextResolutionMiddleware`, so rows S1-S8 apply unchanged. Specifics: GraphQL WebSocket `connection_init` uses the same resolver via `JwtSocketTokenValidator` (claims transformation) and rejects S2/S5/S6 non-CA with the existing "tenant unresolved" rejection; MCP stdio has no principal claim: tenant = `--tenant` argument, else D, else the runner refuses to start (exit code, message `TENANT_UNRESOLVED`); SCIM tokens carry their realm: realm binding, `Unbound` realm follows S3/S6; ReBAC: the default tenant is a normal tenant, so S3 callers may use ReBAC for D (today Legacy is 403); `GatewayExecutionService` (O-4): verified that an unauthenticated principal reaches header selection only after `IsAnonymousAccessAllowed` built an authenticated `InsecureAnonymousAuth` principal, so the `isAnonymousDev` branch is dead; it is deleted (header selects only for CA), the dev-anonymous principal follows S3/S6.

## 3. Architecture decisions

- **DT-A-1 Option.** `Gateway:Tenancy` keeps one key: `DefaultTenantId` (string?, absent or null = no default). `TenancyOptions.Mode`, `IsExplicit`, `IsValid`, `EffectiveMode`, `TryParseMode` and `enum TenancyMode` are deleted. Validator (`GatewayCoreOptionsValidator`): when the key is present it must parse with `TenantId.TryParse` (empty or whitespace string = startup failure, not "unset"), must not be a reserved id (DT-A-6) and must not collide case-insensitively with any other configured tenant id (`TenantCollisionGuard.ConfiguredTenantIds`). Tests `DefaultTenant_Empty_Fails_Startup`, `DefaultTenant_Invalid_Format_Fails_Startup`, `DefaultTenant_Reserved_Fails_Startup`, `DefaultTenant_Collision_Fails_Startup`. The unknown-key guard of #369 then rejects `Gateway:Tenancy:Mode` and `Gateway__Tenancy__Mode` (`Tenancy_Mode_Key_Fails_Startup_As_Unknown`). `ForwardAuth.DefaultTenantId` is deleted (second default concept; a ForwardAuth principal without trusted tenant header has no claim and follows S3/S6), so its key also fails startup.
- **DT-A-2 Resolver (the only default-assignment decision).** `Autheris.Application.Tenancy.ITenantResolver` (singleton `TenantResolver`, options monitor): `TenantId? DefaultTenant { get; }`, `TenantResolution Resolve(ClaimsPrincipal? principal)`, `bool IsDefaultTenant(TenantId)`. Pure core `static TenantResolution Decide(ClaimTenant claim, TenantId? defaultTenant)` for table tests. `TenantResolution` = `readonly record struct (TenantResolutionOutcome Outcome, TenantId? Tenant)` with `Outcome ∈ {Unauthenticated, FromClaim, FromRealm, DefaultAssigned, Unresolved, Invalid}` and `TenantId RequireTenant()` (throws `TenantUnresolvedException`/`TenantClaimInvalidException`, both `GatewaySecurityException`, 403, codes `TENANT_UNRESOLVED`/`TENANT_CLAIM_INVALID`, fixed messages, no value echo). `ClaimTenant` (`Absent | Valid(TenantId) | Invalid`) comes from `TenantClaimReader.Read(principal)` (Domain, replaces the 12-file claim chain; one claim-name list).
- **DT-A-3 One call site per ingress.** `EnterpriseClaimsTransformation` (HTTP and, via `JwtSocketTokenValidator`, WebSocket) calls `Resolve` once and stamps `tenant_id` (only for `FromRealm`/`DefaultAssigned`) plus `autheris:tenant_source` (`claim|realm|default`), after removing any token-supplied `autheris:tenant_source`. Non-HTTP principals (`GatewayExecutionService` dev anonymous, MCP stdio session, ext_authz authenticated path) call the same `Resolve`. `Sid.GetTenantId()` becomes claim-only: returns the stamped/claimed tenant or throws `TenantUnresolvedException`; it never returns a sentinel. `TenantResolutionMiddleware` is deleted; `TenantIdItemKey` moves to `SecurityPrincipalContext` (one item key; the dual key at `SecurityContextResolutionMiddleware:284` goes). Header alias `X-Tenant-Id` constants are deleted (HTTP header names are case-insensitive).
- **DT-A-4 Unresolved is representable.** `SecurityPrincipalContext.TenantId` keeps its type but its getter throws `TenantUnresolvedException` when unresolved; new `TenantId? ResolvedTenant` and `TenantResolutionOutcome TenantSource`. `Anonymous()` has no tenant. `CallerSecurityContext` is only built from a resolved context. Middleware gate in `SecurityContextResolutionMiddleware` (after `UseAuthorization`): authenticated, not CA, unresolved, endpoint without `IAllowAnonymous` → 403 `TENANT_UNRESOLVED` before collision guard and registry. `GatewayExceptionHandler`/`GatewayDenialStatusMapper` map the two new exceptions (governed codes, #368).
- **DT-A-5 Claim versus default (default taken).** The claim wins; D only fills claim-less principals and never overrides or rejects a valid claim. Rationale: overriding mixes tenants, rejecting reintroduces a mode switch; strict pinning already exists as an explicit realm `Fixed` binding; new claim tenants stay bounded by the tenant registry budget. A realm without `FixedTenantId` and without claim mapping (today `Fixed(Legacy)`, `IdentityRealmRegistry:113`) becomes `TenantBindingKind.Unbound` (claim ignored, D applies, S3/S6); `IdentityRealm.ResolveTenant` returns `RealmTenant.Unbound | Bound(TenantId)` and throws on a malformed spec instead of returning Legacy.
- **DT-A-6 Platform scope bucket.** `TenantId.Platform` (`"_platform"`, reserved, case-insensitive) is the tenant of tenant-less platform records only: auth-failure aggregation without tenant, startup audit events, and the DEF `ConsentGrantSqlCore.IntegrityAuditTenant` (interim `=> LegacySingleTenant`, becomes `=> TenantId.Platform`; DEF-SC-04 single reference kept). Arch test `Platform_Tenant_Is_Referenced_Only_By_Audit_Writers` (DEF Phase 3 P-3 ruling: never used for a non-audit decision). It is never a request tenant: claim, header, realm `FixedTenantId`, D and OpenMetadata mappings equal to a reserved id are invalid (`IdentityRealmOptionsValidator` rejects `Platform` instead of Legacy). Platform audit rows are readable by CA only.
- **DT-A-7 Catalog owner.** `CallerScope.Unrestricted` and `CallerScope.Claimless` are deleted; `CallerScopeResolver.Resolve(ClaimsPrincipal?, TenantResolution)`. `CatalogVisibility`/`FilterToTenant`/`DropForeignVirtualTables`/discovery tiers take `TenantId? catalogOwner` (= D) instead of `TenancyMode`: the default tenant is the catalog owner (unfiltered physical catalog, all discovery tiers), which preserves today's single-tenant GA view; every other tenant keeps the consent/`SharedTables` filter; foreign virtual tables are always dropped (also for D). The same predicate `IsDefaultTenant` replaces the six mode-blind widenings (`tenant == Legacy` in OData endpoint/handler, dbt, lineage, `CatalogVisibility:251`, `PrincipalResolverService:44`: config users without tenant belong to D). `SemanticTenancy` keys always by tenant.
- **DT-A-8 Audit of the decision.** Startup: one audit event `TENANCY_DEFAULT_TENANT_CONFIGURED` (platform bucket, details `{DefaultTenantId}`) and the startup log line (configured id, or "not configured: principals without tenant claim are rejected"). Per request: no audit row (volume); `autheris:tenant_source` claim, `SecurityPrincipalContext.TenantSource`, activity tag `autheris.tenant.source`, counter `autheris_tenant_default_assignments_total`. Audit hash inputs are unchanged.
- **DT-A-9 No silent fallback anywhere.** Unparsable or NULL stored tenant values throw a governed integrity exception (reuse DEF `ResolveConsentTenant` for consents; new `StoredTenant.Parse(raw, errorCode)` in Infrastructure for audit/lint readers, code `STORED_TENANT_INVALID`); writers require a tenant (`ArgumentException` on default `TenantId`); `AuditChainEngine`/`AuditCanonicalizer`/`AuditContext` have no tenant default; literals `TenantId("default")`/`?? "default"` (lineage, CDC, datasource testing, ext_authz) use the resolved tenant; `ConsentCacheService` tenant-less overloads are deleted; `OpenMetadataOptions.DefaultTenantId` defaults to null and falls back to D, and an entry with neither mapping nor D is skipped with a warning.
- **DT-A-11 Explicit realms only (DEF O-1, owner-decided 2026-10-26, WP-DT-5).** The five implicit realms (`workforce-entra-legacy`, `corp-adfs-legacy`, `legacy-basic`, `legacy-forwardauth`, `legacy-kerberos`, `IdentityRealmRegistry.cs:146-283`, all GatewayRoles) `IdentityRealm.IsImplicitLegacy` (`IdentityRealm.cs:94`, `WebSocketAuthInterceptor.cs:548`) and the un-namespaced workforce group compat in `RoleResolver.cs:72-104` (groups are always `<realmId>|<groupId>`) are deleted. A startup check fails when an enabled scheme (`EntraId`, `Adfs`, `BasicAuth`, `ForwardAuth`, Kerberos) has no explicit realm of the matching `IdentityRealmKind` in `Authentication:Realms` (the actual bound section, `IdentityRealmsOptions.SectionName`; message names the scheme and the missing kind). Explicit realms grant only their `AllowedGatewayRoles`. Realm tenant binding: `FixedTenantId` or `TenantClaimName`+`TenantClaimMapping` as today; a realm with neither binds to D (`Unbound`, resolved by the resolver, DT-A-5); a realm with neither while D is unset fails startup (`Realm_Without_Binding_And_Without_Default_Fails_Startup`; default taken: startup failure rather than runtime 403, so the misconfiguration shows at deploy time). ClaimMapped realm: claim absent follows S3/S6, claim present but unmapped is `TENANT_CLAIM_INVALID`. Also `Workforce_Groups_Are_Always_Realm_Namespaced`. Shipped configs that enable a scheme get an explicit realm: `src/Autheris.Api/appsettings.json`, `appsettings.Development.json`, `deploy/containers/gqlgateway-api/appsettings.Benchmark.json`, `benchmarks/load/configs/gql-gateway/appsettings.bench.json`, Helm `templates/_helpers.tpl` (+ values). The WebSocket `IsImplicitLegacy` filter goes with DT-A-3. Tests `Enabled_Scheme_Without_Realm_Fails_Startup` (theory over the five schemes), `No_Implicit_Realm_Is_Registered`, `Explicit_Realm_Grants_Only_Allowed_Roles`, `Shipped_Configs_Start` (config golden per shipped file).
- **DT-A-12 Header tenant selection in execution (DEF O-4, owner-decided, WP-DT-4).** Verified: `GatewayExecutionService` replaces an unauthenticated principal by an authenticated `InsecureAnonymousAuth` principal only when `IsAnonymousAccessAllowed`, else throws `GatewayUnauthorizedException`; the later `isAnonymousDev` header branch is therefore dead. No documented `danger_allow_anonymous_access` reason for header selection exists. The branch is deleted: `X-Tenant-ID` selects a tenant only for a canonical ClusterAdmin (same rule as `SecurityContextFactory`); a differing header from any other principal, including the dev-anonymous one, is rejected (`GatewaySecurityException`, 403 `CROSS_TENANT_ACCESS_FORBIDDEN`, no state change); the dev-anonymous principal gets D only (S3), without D it is unresolved (S6). Mandatory tests `Anonymous_Principal_Tenant_Header_Is_Rejected` and `Execution_Unauthenticated_Header_Cannot_Select_Tenant` (theory: anonymous switch on/off, header equal/different/malformed).
- **DT-A-13 Revocation lookup always fails closed (DEF O-2, owner-decided, WP-DT-5).** Delete `RedisOptions.FailClosedOnRevocationLookupError` and `ResolveFailClosedOnRevocationLookupError` (`RedisOptions.cs:106-115`) and the `!_failClosed` accept branch in `RedisTokenRevocationService.HandleLookupFailure` (`:206-215`, metric `lookup_fail_open`); `RevocationLookupGraceSeconds` is unchanged. The removed key goes into `LegacySwitchGuard` (from DEF, fails on presence). Tests `Revocation_Lookup_Error_Rejects_Token_In_Development`, `FailClosedOnRevocationLookupError_Key_Fails_Startup`.
- **DT-A-10 DI.** New singletons `ITenantResolver`; `SemanticTenancy` factory changes. Regenerate `composition-dev-sqlite.txt` and `composition-production-like.txt` (#367 snapshots) and `startup-validator-warnings.txt` in the commit that changes them.

## 4. Stored data (no migrations)

Today Legacy is stored as the literal `legacy-single-tenant` in every tenant column. After DT every row carries the resolved tenant (D for claim-less callers). Baseline schemas (3 dialects) drop `DEFAULT 'legacy-single-tenant'` from `CONSENTS.tenant_id` and `AUDIT_LOG_ENTRIES.tenant_id` (stay NOT NULL) and make `CONSENT_REQUESTS.tenant_id` NOT NULL; schema-shape tests (`PostgreSqlGovernanceSchemaShapeTests`, `SqlServerGovernanceSchemaShapeTests`, SQLite shape) are updated. `RebacSeedHostedService` seeds its tuples for D, and skips with a warning when D is unset; `DeniedTablesStartupReporter` enumerates configured tenants plus D. Existing dev databases keep their `legacy-single-tenant` rows; `legacy-single-tenant` is a valid tenant id, so setting `DefaultTenantId: legacy-single-tenant` keeps them readable (documented; default taken: not forbidden). Webhook/CDC nullable tenant columns (platform events) are unchanged. Test fixtures `governance-v1.1.8-preshim.sqlite.sql` and the SqlCompilerGate corpus keep the literal as data.

## 7. Breaking changes (release notes)

1. `Gateway:Tenancy:Mode` removed; any value fails startup (unknown key). Replace `Single` by `Gateway:Tenancy:DefaultTenantId: <id>`; `Multi` = omit the key.
2. `Gateway:Authentication:ForwardAuth:DefaultTenantId` removed (unknown key); use `Gateway:Tenancy:DefaultTenantId`.
3. Without a default tenant, an authenticated non-ClusterAdmin principal without tenant claim gets 403 `TENANT_UNRESOLVED` on every protected endpoint (was: consent-path-only "claimless" access in the legacy tenant).
4. Invalid tenant claim: 403 `TENANT_CLAIM_INVALID` (was 403 `CROSS_TENANT_ACCESS_FORBIDDEN`).
5. New writes store the configured default tenant id, not `legacy-single-tenant`; old dev data stays readable only with `DefaultTenantId: legacy-single-tenant`.
6. Baseline schema: no column default on `CONSENTS.tenant_id`/`AUDIT_LOG_ENTRIES.tenant_id`; `CONSENT_REQUESTS.tenant_id` NOT NULL.
7. ReBAC endpoints now work for the default tenant (were 403 for the legacy tenant).
8. Tenant-less platform audit events (auth failures, startup) go to the reserved `_platform` tenant, readable by ClusterAdmin only; `_platform` is rejected as a tenant value everywhere.
9. MCP stdio needs `--tenant` or a default tenant; OpenMetadata entries without mapping and without default tenant are skipped.
10. GraphQL WebSocket: the multi-tenant heuristic is gone; unresolved tokens are rejected in both deployment shapes.
11. Implicit identity realms removed (DT-A-11): enabling `EntraId`, `Adfs`, `BasicAuth`, `ForwardAuth` or Kerberos without an explicit `Authentication:Realms` entry of the matching kind fails startup; explicit realms grant only their `AllowedGatewayRoles` (implicit realms granted all roles).
12. `X-Tenant-ID` is honoured only for cluster administrators; the development anonymous principal (`danger_allow_anonymous_access`) uses the configured default tenant only (DT-A-12).
13. A failed token revocation lookup always rejects the token, also in Development; `FailClosedOnRevocationLookupError` is removed and its presence fails startup (DT-A-13).
14. Workforce groups are always realm-namespaced (`<realmId>|<groupId>`); consents on un-namespaced workforce group SIDs no longer match (DT-A-11).
15. A realm without `FixedTenantId`/claim mapping binds to the default tenant; without a default tenant it fails startup (DT-A-11).
