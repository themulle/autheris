## 1. Problem Statement & Customer Impact

### Issue #67: OData Feed Import in Microsoft Excel Fails Due to Raw Unescaped Newlines in CSDL Attributes
* **Observation:** When attempting to load an Autheris OData feed (`http://localhost:8080/odata/v4`) into Microsoft Excel (Data → Get Data → From Other Sources → From OData Feed), Excel aborts with a modal error dialog:
  > *"OData: The feed's metadata document appears to be invalid. Error: Operation is not valid due to the current state of the object."*
* **Root Cause:** In `ODataCsdlGenerator.cs`, `Annotation` elements (`Core.Description`, `Core.LongDescription`) for entities and properties were written as `String="<escaped>"` using `System.Security.SecurityElement.Escape`. That standard method only escapes `<`, `>`, `&`, `"`, and `'`. When multi-line descriptions (such as protobuf comments, dbt models, or multi-line documentation) are emitted, raw unescaped ASCII newline (`0x0A`) and carriage return (`0x0D`) characters are placed inside XML attribute quotes. While generic XML parsers normalize these into spaces, Excel's strict OData parser rejects documents containing raw newlines within attribute values.
* **Customer Impact:** Excel and PowerQuery users are entirely unable to load data from Autheris OData v4 endpoints without an intermediate proxy re-writing metadata.

### Issue #66: Missing Supported Query Options ($filter, $orderby, $count, $format) in Dynamic OpenAPI Specification
* **Observation:** The OpenAPI 3.1 specification generated by `DynamicOpenApiGenerator.cs` (served at `/odata/v4/$openapi`, `/odata/v4/{domain}/openapi.json`, and Swagger UI) only advertises `$select`, `$top`, and `$skip` as query parameters. The operation description explicitly states *"Supports $select, $top, $skip. Other system query options are rejected (400/501), never ignored."*
* **Root Cause:** When `DynamicOpenApiGenerator.cs` was originally authored, `$filter`, `$orderby`, `$count`, and `$format` were not yet completed. Since then, `ODataEndpoints.cs`, `ODataHandler.cs`, and `ODataFilterParser.cs` fully implemented and hardened `$filter`, `$orderby`, `$count`, and `$format`. However, `DynamicOpenApiGenerator.cs` was never updated to advertise these options.
* **Customer Impact:** Swagger UI users cannot enter filters or sorting parameters in the interactive UI. Code generation tools (OpenAPI Generator, Kiota) and API consumers assume that Autheris does not support filtering or sorting on OData endpoints.

## 2. Requirements & Acceptance Criteria

### Functional Requirements

1. **CSDL XML Attribute Entity Escaping (Issue #67):**
   - All attribute values in the generated CSDL XML (schema namespace, entity names, property names, keys, and descriptions) must strictly escape carriage returns (`\r` → `&#13;`), newlines (`\n` → `&#10;`), and horizontal tabs (`\t` → `&#9;`) in addition to standard XML characters.
   - Raw newlines (`\r\n`, `\n`) must NEVER appear literally within XML attribute quotes.
   - The emitted CSDL XML must remain 100% compliant with OASIS OData v4 CSDL specifications and valid against OASIS XSD schemas (`edm.xsd`, `edmx.xsd`).
   - Excel OData feed import must successfully load all tables without errors.

2. **OpenAPI Query Parameter Advertisement & Documentation (Issue #66):**
   - `DynamicOpenApiGenerator.cs` must advertise all 7 actively implemented query options:
     - `$select`: Comma-separated property projection.
     - `$top`: Maximum record count (bounded to max 1000, default 100).
     - `$skip`: Offset pagination (bounded to max 100,000).
     - `$filter`: OData v4 filter expression with supported operators (`eq`, `ne`, `gt`, `ge`, `lt`, `le`, `and`, `or`, `not`), functions (`contains`, `startswith`, `endswith`, `tolower`, `toupper`), and bounds (max length 4096, max depth 32).
     - `$orderby`: Comma-separated property sorting with direction (`asc` or `desc`).
     - `$count`: Boolean indicator (`true` or `false`) to project total row count.
     - `$format`: Media type negotiation (`json` or `parquet`).
   - Path operation descriptions must accurately state: *"Supports $select, $top, $skip, $filter, $orderby, $count, $format. Other system query options are rejected (400/501), never ignored."*
