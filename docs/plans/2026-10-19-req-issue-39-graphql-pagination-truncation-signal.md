## 1. Executive Summary & Problem Statement

### 1.1 The Problem
In Autheris GraphQL, `PaginationTruncationMiddleware` is registered in the Hot Chocolate pipeline to inspect `context.ContextData[PaginationTruncationMiddleware.ContextKey]` (`"PaginationTruncated"`) and emit `extensions.pagination: { isTruncated: true, maxRowsReached: true }`.

However, **no component in `src/` ever sets this context key**. When a client query requests a large list or omits a limit, `GraphQlTreeBuilder` and `GovernedTreeQueryService` clamp or slice results at `MaxResponseRows` (default 5,000 / 1,000) or client `first` argument. Because the middleware never sees the flag, the response returns HTTP 200 with truncated data and **no indication of truncation** in `extensions`.

Downstream systems (data export jobs, synchronization workers, autonomous AI agents) misinterpret the returned array as the complete dataset. This silent truncation leads to data loss, incomplete reports, and broken state synchronization.

### 1.2 Target Audience
- **API Consumers & Client Integrators:** Must know with certainty whether they have consumed all matching rows or reached a gateway cap.
- **Autonomous AI Agents:** Need deterministic truncation signals to trigger follow-up pagination calls.
- **Security & Compliance Officers:** Enforce that system caps (`MaxResponseRows`) cannot mislead callers into believing they possess full audit or analytical sets.

### 1.3 Strategic & Architectural Fit
Autheris is an enterprise gateway adhering to **Fail-Closed and Explicit Semantics**. Returning a partial dataset disguised as a complete dataset is an integrity hazard. Providing explicit pagination extensions and cursor guidance on root fields ensures unambiguous consumption.

## 2. Market & Industry Benchmark

- **GraphQL Foundation & Relay Cursor Connections Spec:** Recommends explicit `pageInfo { hasNextPage, hasPreviousPage }` or gateway-level protocol extensions when slicing occurs.
- **Apollo GraphQL Router:** Attaches `@stream` / `@defer` protocol indicators or response extensions when gateway-level row limits terminate execution early.
- **OWASP API4:2023 (Unrestricted Resource Consumption):** Dictates strict gateway bounds on collection queries while mandating that pagination signals accompany truncated results to prevent API abuse and client synchronization loops.

---

## 3. User Stories & Acceptance Criteria

### US-1: Slicing Notification at MaxResponseRows
*As an API Consumer, when my query returns rows capped by `Gateway:GraphQL:MaxResponseRows`, I want `extensions.pagination.isTruncated: true` and `extensions.pagination.maxRowsReached: true` in the JSON response, so that my application can notify the user or initiate pagination.*

- **AC-1.1:** When the database returns rows that equal or exceed `MaxResponseRows`, or when `CatalogGraphQlTypeModule` slices the result at `MaxResponseRows`, `ctx.ContextData["PaginationTruncated"]` is set to `true`.
- **AC-1.2:** `PaginationTruncationMiddleware` attaches `extensions.pagination: { "isTruncated": true, "maxRowsReached": true }` to the operation result.
- **AC-1.3:** When the query returns fewer rows than `MaxResponseRows` and fewer than the requested `first` limit, `extensions.pagination` is omitted (or set to `isTruncated: false`).

### US-2: Client-Specified Limit Lookahead Slicing
*As an AI Agent or Developer specifying `first: 50`, I want to know if there are more rows beyond the 50 returned without fetching another page.*

- **AC-2.1:** For root queries, `GovernedTreeQueryService` queries with lookahead `limit + 1` (or checks total available count when pushdown allows).
- **AC-2.2:** If `limit + 1` rows are returned by the data source, the service slices the returned list to `limit` rows and marks `PaginationTruncated = true` with `maxRowsReached = false` (or `maxRowsReached = true` if `limit >= MaxResponseRows`).
- **AC-2.3:** `extensions.pagination` indicates `{ "isTruncated": true, "maxRowsReached": false, "pageSize": 50 }`.

### US-3: Root List Cursor & Pagination Guidance
*As an API Developer inspecting the GraphQL schema, I want clear documentation on root list fields detailing how to paginate.*

- **AC-3.1:** All root table query fields generated by `CatalogGraphQlTypeModule` contain schema field descriptions detailing supported arguments (`first`, `offset`) and guidance to use declared primary keys (`TableKeyDefinition`) for stable keyset pagination.
- **AC-3.2:** If an offset exceeds `MaxAllowedOffset` (default 10,000), a descriptive error `INVALID_QUERY` is returned with guidance on keyset filtering.

## 4. Non-Functional Requirements (NFRs)

- **Performance & Zero Allocation:** Setting the truncation flag must not allocate tracking objects or copy lists unless truncation actually occurs. Hot-path execution overhead must remain $< 0.05$ ms.
- **Resilience & Thread-Safety:** Context data updates must use thread-safe dictionaries or `lock (ctx.ContextData)` consistent with `CatalogGraphQlTypeModule`.
- **Backward Compatibility:** Existing clients that ignore `extensions` are unaffected. Existing valid queries continue to return the expected array under `data`.

---

## 5. Security & Governance Review

- **Information Leakage Defense:** The pagination extension signals only boolean truncation and count caps. It must not reveal total table row counts or internal database statistics that bypass column/row governance.
- **Audit Logging:** Truncated requests must record `truncated: true` in the query audit log (`AuditEventTypes.QueryExecution`) to assist FinOps and usage analytics.

---

## 6. Implementation Scope

1. **`CatalogGraphQlTypeModule.cs`:**
   - In `ResolveRootQueryAsync`, evaluate returned `list.Count` against `maxResponseRows` and requested `queryNode.Limit`.
   - Set `ctx.ContextData[PaginationTruncationMiddleware.ContextKey] = true` whenever results are truncated by limit or gateway caps.
2. **`PaginationTruncationMiddleware.cs`:**
   - Enrich `extensions.pagination` dictionary with granular flags (`isTruncated`, `maxRowsReached`).
3. **Unit & Integration Tests:**
   - Test queries returning exact count vs capped count.
   - Verify `extensions.pagination` presence and correctness in HTTP GraphQL responses.
