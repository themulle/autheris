# Release 1.9.0 candidate proposal

Status: proposal for owner decision (2026-11-19). Nothing is tagged, released, merged or closed by this document. `CHANGELOG.md` on main is untouched; the draft below is for the cut commit.

Basis: 290 commits between `v1.8.5` and `origin/main` (about 56 merged PRs, #803 to #897), plus the open PRs listed below. Parent plan: `00-master-plan-overview.md`.

## Scope proposal

### Themes

1. **Governance simplification (WP-SIMPL-52, 46, 31, 20).** Dead tiers, roles, columns and the SQLite leftovers are removed. Schema steps 0023 to 0028 drop `is_sensitive`, the superseded role and access-policy tables, row-filter subquery columns, and the legacy ticket and visibility columns.
2. **Discovery and catalog.** Linked documents and applications (WP-SIMPL-41 PR 6, 6b), `read_document`, `accessStatus` on search and a filter (#798, #804), text query on `/catalog/objects` (#857), `rowScopeDescription` (#858), the slim `describe_dataset` brief (#799), restored keys, indexes and required filters (#805, #807), bounded catalog caches (#678), discovery-hidden documents.
3. **Data products (WP-SIMPL-49 A1 to A6).** Product model, view and procedure products, cluster-wide cache with idle drop, Git synchronisation with signed webhook, discovery, usage, audit and explain; hardening (#851).
4. **Classification and golden queries.** Classification admin API and per-classification clear requests (WP-SIMPL-52 PR 5), masked catalog text (PR 4b), golden queries from dbt meta (WP-SIMPL-54, #580), the access-request flow without the tier model (WP-SIMPL-41 PR 5).
5. **GraphQL freshness.** Prompt schema rebuild after catalog writes and the authenticated `graphql-schema-status` route (#802).
6. **Consent apply correctness.** `consents/apply` is idempotent and compares more fields (#806, #828).

### Breaking changes in open PRs

- #868: audit archive (WORM) export removed; every key under `Gateway:Audit:Worm` fails startup, including `false` and empty. The chain-anchor WORM directory store and the WORM configuration audit stay.
- #900: role grantees removed end to end (`GranteeType.Role`, REST and GraphQL `roleName`). Role input is refused at every entry point; step 0029 aborts while an active role grantee exists.
- #892: caller parameters `p0`, `p1`, ... are accepted (before: 403); only the `__`, `gql_` and `autheris` prefixes stay reserved. Keys differing only in case (`p0` and `P0`) answer 400.
- #867 (expression guard, #847): under a row policy or tenant predicate only non-raising expressions pass, everything else is refused with the existing fixed message. Time bucketing for time zones with a non-whole-hour offset is refused under a tenant predicate.
- #865 (denied-column rule, #871): one rule on every channel; only Clear or Masked columns of a granted table are named or counted. `get_table_schema` returns no columns for an ungranted table. The REST detail still lists Deny columns for the request-access flow.
- #886 (not breaking, new config): `SubjectRoles` on a `GenericOidc` realm and a per-realm JwtBearer scheme `Bearer:realm:<id>`.

## Upgrade notes

### Migration order and policy

v1.5.0 is the frozen schema base. Later versions migrate forward-only to the newest DB version; older databases are unsupported. Steps run automatically at startup in numeric order. All nodes must run the new build before a destructive step applies (rolling mixed versions are not supported across drops).

| Step | Effect | Destructive |
| --- | --- | --- |
| 0023 `drop_is_sensitive` | Migrates sensitive columns into mask overrides and consent clearance, drops `column_masking_rules` and `table_columns.is_sensitive` | Yes |
| 0024 `drop_superseded_governance_columns` | Drops `roles`, `role_members`, `access_policies`, `access_policy_grantees`, `access_policy_selectors` and the row-filter subquery columns (`dependent_table`, `foreign_key_column`, `subquery_predicate_json`, and related) | Yes |
| 0025 `golden_queries` | Creates `golden_queries` | No |
| 0026 `doc_links` | Creates `doc_links`; adds `discovery_hidden` to official and tenant documents | No |
| 0027 `drop_legacy_governance_columns` | Drops `consent_requests.itsm_ticket_id` with `ux_consent_requests_ticket` and `table_catalog_settings.visibility` | Yes |
| 0028 `data_products` | Creates `data_products`, `data_product_versions`, `data_source_owners` | No |
| 0029 `drop_role_grantee` (only if #900 lands) | Aborts with the row id while an active role grantee exists; retires pending role consent requests (REJECTED); deletes revoked role rows; drops `role_id`, `role_name` and their index | Yes |

Both PostgreSQL and SQL Server carry every step; checksums are pinned in the architecture goldens.

### Before upgrading

- Take a full backup of the governance database. There is no downgrade.
- Remove `Gateway:CatalogSearch:Enabled` and `Gateway:Catalog:DefaultVisibility` (and `Gateway:Audit:Worm:*` if #868 lands) from every configuration source.
- Move a loopback Ollama endpoint to a trusted internal host.
- With #900: convert role grantees to groups before upgrading, otherwise step 0029 aborts startup.
- Clients: handle the slim brief, `404`-like answers for hidden documents, and 400 on blank or comma scopes.
