## #476 CDC custom query poller

**Verified.** `CustomQueryPollerService.cs:371-404` returns `null` for every provider except SQLite/PostgreSQL. The provider is **sniffed** from `conn.GetType().Name`, the connection string and `conn.DataSource` (substring "sqlite"/"postgres"): a SQL Server host or database named `postgres-x` gets `SET TRANSACTION READ ONLY` (error), an Oracle source is never read-only. **`CustomQueryPollerValidator` (single SELECT AST, `INTO`, `EXEC` checks) is registered (`CustomQueryPollerServiceExtensions.cs:20,34`) but has no caller in `src/`** (only tests); the code comment says the shape "is enforced by" it. So today nothing checks the statement shape at runtime; the read-only transaction is the only guard. Pollers come from `Gateway:CustomQueryPoller` (operator config, `Enabled=false` default, `IOptionsMonitor` hot reload).

**Threats.**
- Fail-open default plus provider sniffing: unknown provider runs the template with a write-capable login.
- SQL Server: a rolled-back transaction is not a guard. DDL and `EXEC` of non-transactional procedures (`xp_`, `BACKUP`, linked servers, `sp_configure`) survive a rollback, `ApplicationIntent=ReadOnly` only routes to a secondary and enforces nothing on a primary. With the validator unwired, a multi-statement template is possible.
- Hot reload swaps `Pollers` without validation; poller with a `WriteConnection` data source (WP-45 PR 5) would run reads on a write credential.

**Conditions.**
- SEC-OI-476-1: wire `CustomQueryPollerValidator` in two places: options validation at startup and on every `IOptionsMonitor` change (invalid reload disables that poller and keeps the last valid one, never runs the new text), and again before each poll (cheap, text-hash cached). The validator becomes mandatory for **every** provider; SQL Server and Oracle rely on it plus the read-only login, and the code comment says so.
- SEC-OI-476-2: dialect comes from the registered data source (`DatabaseDialect`, exhaustive `switch`, unknown enum value throws), never from type, connection string or host name sniffing. Admitted: PostgreSQL, SQL Server, Oracle, SQLite (until WP-SIMPL-31); Databricks and unknown fail options validation, not the first poll (Q-SECDP-6).
- SEC-OI-476-3: PostgreSQL: begin transaction, `SET TRANSACTION READ ONLY` as first statement, execute, always roll back, never commit. Oracle: `SET TRANSACTION READ ONLY` as first statement of the transaction. SQL Server: transaction rolled back in `finally`; the poller never calls `Commit`. A failure to establish the mode is fatal for the poll (no fallback to plain execution).
- SEC-OI-476-4: the poller uses the data source's read connection only; a `WriteConnection` is never resolved for CDC (WP-45 step 11). `OwnerTenantId` must equal the tenant that owns the data source; mismatch fails options validation (verify the resolver while implementing).
- SEC-OI-476-5: poll errors log type, stream name and SQL state, not `ex.Message` (driver messages quote statement text and row values).
- Tests: `CustomQueryPollerReadOnlyTests.Unsupported_provider_throws`, `.Provider_is_not_sniffed_from_host_name` (SQL Server connection to host `postgres-db`), `.Validator_runs_before_first_poll_and_on_reload`, `.Invalid_reload_keeps_last_valid_poller`, `.Multi_statement_template_rejected_on_sql_server`, `.Write_connection_never_used`, `.Oracle_sets_read_only_transaction_before_query`, `.SqlServer_rolls_back_never_commits`; integration `Write_in_query_template_is_refused_by_database` (PostgreSQL, SQL Server rollback check, Oracle nightly). Plan test names kept.

**WP-45 PR 5 conditions** (it owns outcome audit, idempotency, budget, `WriteConnection`; already in the spec: SEC-SIMPL-128..131; these add what the spec leaves open):
- SEC-OI-505-1: an intent without a terminal record (process crash between outcome audit and commit) is a defined state `indeterminate`: the idempotency key stays reserved (replay returns `409 write_outcome_indeterminate`, never re-executes) and the privileges/migration report lists unresolved intents older than 15 min. A replay never runs a statement a second time on any uncertainty.
- SEC-OI-505-2: the budget is reserved atomically **before** execution for `MaxAffectedRows` (Redis `INCRBY`/Lua, in-memory lock) and settled to the actual count; a store error denies (503/429), never allows. In cluster mode the in-memory store fails startup outside Development (per-node budgets multiply the limit, SEC-SIMPL-34 pattern).
- SEC-OI-505-3: the outcome record `WEBSQL_DML_EXECUTED` runs in `beforeCommit` with `CancellationToken.None`, required; its failure rolls back and returns the same fixed error as any DML failure. After a commit failure only `WEBSQL_DML_FAILED` (intent id) is written; the swallow at `GovernedSqlExecutor.Audit.cs:84-90` is deleted for the outcome path and no `LogCritical(ex, ...)` with the exception object remains (driver text).
- SEC-OI-505-4: audit field names of the DML records (`written_columns`, `idempotency_key_hash`, `value_hash`) pass the SEC-OI-473 chokepoint unredacted by test (they are on the allow-list or the allow-list is extended in the same PR); values are never audited. - Tests: `DmlOutcomeAuditTests.Crash_between_outcome_and_commit_leaves_indeterminate_intent`, `.Replay_of_indeterminate_key_is_409_and_not_executed`, `WriteBudgetTests.Concurrent_statements_cannot_overshoot_hourly_rows`, `.Store_unavailable_denies`, `.InMemory_store_in_cluster_mode_fails_startup`, `DmlAuditFieldRedactionTests.Dml_audit_fields_survive_redaction`.

**DP-14 (read-only reads).** Verified `DbSessionContextInitializer.cs`: PostgreSQL uses `SET LOCAL` only inside a transaction, but with `requireTransaction: false` the session values are **not** local (pooled connection); Oracle and SQL Server run without a transaction (`tx: null`); the initializer is shared by non-user-read callers (system reads, purposes). A read-only mode applied there leaks onto pooled connections or breaks the write path.
- SEC-OI-505-5: read-only mode is requested explicitly by the user-read path (`AccessMode.ReadOnly` parameter, default off), never inferred in the shared initializer. PostgreSQL: `SET TRANSACTION READ ONLY` inside the explicit transaction only (never `SET SESSION CHARACTERISTICS`, never `default_transaction_read_only`). SQL Server and Databricks stay on the read-only login; SQLite (`PRAGMA query_only`) only if reset before return. An unknown dialect still throws (existing `ResolveDialect`).
- SEC-OI-505-6: it is defence in depth; the AST visitor stays the primary control and the privileges report stays the operator control. Residual (documented in code): Oracle autonomous transactions and PostgreSQL functions that open a new connection are not stopped.
- Tests: plan names plus `ReadOnlyReadSessionTests.Pooled_connection_after_read_only_read_accepts_dml_on_write_path` (PostgreSQL and Oracle), `.Read_only_mode_not_set_without_explicit_request`, `.Failure_to_set_mode_fails_the_read`, `.Unknown_dialect_still_throws`.

## #508 MCP hardening

**Verified, plan partly outdated.** `PersistedToolValidator.cs:50-98`: tools are code-defined (`McpDatasetTools` etc.), so the "persisted tool" is a closed set of trusted schemas. The validator is optional in the executor (`GatewayMcpQueryExecutor.cs:42,75,111`) though registered; it is skipped when arguments are `{}` or empty (executor, before the call), when `arguments` is not an object (**array/string/number pass both checks**), when `InputJsonSchema` is empty (skips validation) or has no `properties`; names are compared `OrdinalIgnoreCase`, the executor then builds a case-insensitive dictionary (last duplicate wins); the failure text echoes parameter name and matched keyword to the client and the log. `SemanticMcpCompiler.VisibleTablesAsync` (`:311-333`) already returns an empty list for a non-null principal without a consent repository; the remaining fail-open is the `principal == null` and no visibility service branch (`:332`) and `IsMcpAuthBypassed`. Prompts (`GatewayMcpServer.cs:328-385`) interpolate `dataset` and `principal`; no tool audits another principal.
- SEC-OI-508-1: the validator is required (constructor injection, no `?`, startup fails when missing) and runs for every call including empty arguments. Closed-world recursive schema validation is the control: non-object arguments rejected (null/undefined means empty object), `additionalProperties=false` by default at every level, type/enum/required/maxLength/min/max checks, empty or unparseable schema = reject (fail closed), duplicate property names rejected, names compared **ordinally** (case-sensitive) and the executor uses an ordinal dictionary. Bounds: arguments JSON at most 256 KiB before parse, depth 8, 1,000 nodes, string 64 KiB.
- SEC-OI-508-2: the English phrase denylist is not a security boundary and is not extended (homoglyphs, other languages, nested encodings bypass it); it may stay as an additional block applied recursively with the same bounds. Rejection text and audit carry a fixed code `invalid_arguments` only: no parameter name, no matched keyword, no value.
- SEC-OI-508-3: prompts: `dataset` through `TryParseDatasetId`, length at most 256; `principal` is dropped (Q-SEC2-3; no tool audits other principals, so the argument only injects text); invalid input answers `InvalidParams` with a fixed message and does not echo the value; control characters and newlines rejected; the prompt text never contains an unvalidated string.
- SEC-OI-508-4: catalog metadata: real owner from the catalog record or the field is omitted; tags only from catalog data; no fabricated address.
- SEC-OI-508-5: `VisibleTablesAsync` returns an empty list in the `principal == null` branch unconditionally; the `IsMcpAuthBypassed` branch stays only as the dangerous-configuration path already refused outside Development (verify the startup check, add a test) and keeps the WP-41 discovery path. The change must keep `McpCatalogVisibility` behaviour for authenticated callers.
- SEC-OI-508-6: multi-valued claims (`McpEndpoints.cs:195`, `GroupBy(c.Type).First()`): the token claim order is IdP-controlled, so first-wins can widen an attribute policy. Use the same resolution as REST/GraphQL: several values for a scalar attribute = Ambiguous = attribute unavailable (Q-SEC2-2); do not invent a multi-value semantic. The scheme marker claim stays excluded from the copy. PR 4c goes **after WP-43 PR 4a** (same `ResolveCaller` claim order, SEC-OI-489-2) and after WP-46 PR 3 (#683 edits `GatewayMcpQueryExecutor.cs`); re-verify line numbers.
- Tests: plan/issue names plus `PersistedToolValidatorTests.Array_arguments_rejected`, `.Empty_schema_rejects`, `.Case_variant_duplicate_rejected`, `.Nested_undeclared_property_rejected`, `.Oversized_or_deep_arguments_rejected`, `.Failure_text_is_fixed_code`, `McpPromptTests.Dataset_argument_with_newline_is_rejected`, `.Principal_argument_not_accepted`, `McpCallerTests.Multi_valued_claim_is_ambiguous_not_first`, `SemanticMcpCompilerTests.No_principal_no_service_returns_empty`.

No partial application.
- SEC-OI-475-4: logs carry table, operation, error type and count; never `ex.Message`, SQL text or values (same for the in-memory store).
- SEC-OI-475-5: the consumer's empty-dictionary placeholder is either implemented with real payload decoding in this PR or the consumer rejects (fences) any change event that carries no decoded values; it must never apply an empty mutation as success.
