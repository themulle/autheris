## #504 Security trait sweep and missing regression tests

**Verified.** The four named classes are untagged (`AccessPlanningTenantBindingTests`, `ApproveConsentRequestFourEyesMutationTests`, `IdentityDeprovisioningServiceTests`, `AsyncQueryJobWorkerConcurrencyTests`: no `Category=Security` found by grep). No `SecurityTraitCoverageTests` exists.

**Threats.**
- A ratchet rule keyed on a namespace segment or file name is bypassed by moving or renaming a class, by a class outside `Security` that is a security test, or by a baseline file that is edited to grow instead of shrink.
- Tagging 156 files adds them to the PR security-filtered subset (and to the #522 selection); a bad merge or a trait typo could silently remove tests while the count test is green (count compared only by number).
- The inventory file is committed text: a stale or hand-edited list gives false assurance for later deletion PRs.
- The new regression tests assert fail-closed behaviour; weak assertions (exception type only) would pass on the wrong denial.

**Conditions.**
- SEC-OI-504-1: the architecture test checks (a) the named classes and (b) every class under a `Security` namespace segment or named `*Security*Tests`, at class **or** method level (including theories); the exemption baseline `security-trait-exemptions.txt` is verified shrink-only by comparing with `git show origin/main:` in CI (an added line fails) and each entry carries a reason; the existing `Security_category_count_does_not_decrease` ratchet stays and is extended to compare the **set of test names** against a committed base (a rename or removal fails unless listed in a `removed-security-tests.txt` with an issue link).
- SEC-OI-504-2: tagging is class-level `[Trait("Category","Security")]`; no test is edited beyond the attribute in the sweep PR except the new tests; the PR description lists the Security test count before and after (TRX totals) and the delta equals the new tests plus the newly tagged ones.
- SEC-OI-504-3: `docs/plans/simplification/security-test-inventory.txt` is generated by a script from `--list-tests --filter Category=Security`, sorted, and a test regenerates it in memory and compares (fails when stale); it contains test names only.
- SEC-OI-504-4: each missing-test item is first verified still untested by name; each new test asserts the specific denial (status code, error code or empty result and **no side effect**: no row written, no event sent, no webhook delivered), not only that an exception occurred; for `Missing_table_returns_403_not_404` it asserts identical responses for hidden and nonexistent tables where the contract says so, and the contract chosen is recorded in the test name or comment.
- SEC-OI-504-5: the tests build their own principals and tenants (no shared static state), and the webhook, quota and HitL tests include the positive control (the allowed subject or enrolled code succeeds) so a broken fixture cannot pass them.
- Tests: the plan names plus `SecurityTraitCoverageTests.Method_level_traits_are_recognised`, `.Baseline_may_only_shrink`, `.Security_test_name_set_does_not_lose_entries`, `SecurityTestInventoryTests.Inventory_file_matches_discovered_tests`, `CdcWebhookDeliveryServiceTests.Allowed_subject_is_delivered_positive_control`, `HitLStepUpApprovalServiceTests.Valid_code_is_approved_positive_control`.

## #613 Culture analyzers

**Verified.** `Directory.Build.props:17` suppresses `CA1307`, `CA1310` (and `CA1304/1305/1311`) in `NoWarn`; `TreatWarningsAsErrors` is already on.

**Threats.** A culture-sensitive `StartsWith/EndsWith/Compare/IndexOf` on an identifier, role, SID, tenant, header or SQL keyword is a bypass class (Turkish-I, ligatures, ignorable characters: `"­admin"` equals `"admin"` under culture comparison). The change itself is a security-relevant behaviour change: a mechanical `OrdinalIgnoreCase` can **widen** matching (case-insensitive where today's culture comparison was case-sensitive) or narrow it (ignorable characters no longer match), and an allow-list becomes broader than intended. `Contains/Replace` are ordinal by default, so a blanket rewrite there is neutral; a sloppy global replace could still turn exact checks into case-insensitive ones.

**Conditions.**
- SEC-OI-613-1: WP-OI-CQ-2a delivers a site table in the PR description (file, member, old semantics, new comparison, reason) for every culture-sensitive `StartsWith/EndsWith/CompareTo/Compare/IndexOf` on string identifiers. Default rule: `Ordinal` unless the surrounding code or contract already requires case-insensitive matching (then `OrdinalIgnoreCase`, with the existing test or a new one showing the contract). A site that is an **allow** decision (role, scope, tenant, SID, header allow-list, SQL keyword allow-list) never moves from case-sensitive to case-insensitive; a **deny** decision never moves from insensitive to sensitive.
- SEC-OI-613-2: security deny lists and keyword guards compare ordinal-ignore-case after the existing normalisation; the guard tests include the bypass inputs (`"INSERT"`, `"ınsert"` with dotless i, `"INSERT"` with soft hyphen or zero-width space where the guard normalises) and assert the existing outcome.
- SEC-OI-613-3: `CultureInvariantComparisonSecurityTests` runs under `tr-TR` **and** `invariant`, covers role, scope, SID prefix, tenant id, header name, and SQL keyword checks through the real services (not copies of the comparison), and asserts the same result in both cultures; plus one test per changed site of SEC-OI-613-1 whose semantics changed.
- SEC-OI-613-4: catalog search keeps its own normalizer; any `#pragma warning disable CA1310` carries a reason comment, is limited to search ranking code, and `AnalyzerConfigurationTests` fails when a `#pragma` for CA1307/CA1309/CA1310 appears in `src/` outside an allow-list file of exemptions that may only shrink; `.editorconfig` severity `error` scoped to `src/**` is asserted by the same test.
- SEC-OI-613-5: 2b is behaviour-neutral by construction: `Contains/Replace/IndexOf(string)` gain `StringComparison.Ordinal` only (never `OrdinalIgnoreCase` unless the code already lower-cases or the contract says so); the PR diff is reviewed for no other change; the build has 0 warnings.
- Tests: the plan names plus `CultureInvariantComparisonSecurityTests.Scope_and_tenant_checks_same_in_tr_TR_and_invariant`, `.Soft_hyphen_does_not_match_role`, `.Changed_sites_keep_allow_decision_case_sensitivity`, `AnalyzerConfigurationTests.Culture_pragmas_only_in_allowlisted_files`.

## Anything the plans missed (summary)

1. The ratchet is by file/namespace and count only: renames and method-level traits slip through (SEC-OI-504-1).
2. Missing-test items need positive controls and side-effect assertions (SEC-OI-504-4/5).
3. The analyzer change itself can widen an allow decision; needs a per-site decision table (SEC-OI-613-1).
4. Ignorable-character bypass (`­`) is not in the plan's `tr-TR` test set (SEC-OI-613-2).
