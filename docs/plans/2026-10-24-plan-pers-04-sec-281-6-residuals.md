## WP-B (SEC-281-6): `ingress.exposeAdmin` and nginx case-insensitive deny
B1. `values.yaml`: replace `blockAdminPath: true` with `exposeAdmin: false` (comment: `true` only on an internal-only ingress, NetworkPolicy stays) and `nginxCaseInsensitiveAdminDeny: true`. Breaking rename allowed; no alias.
B2. `templates/ingress-traefik.yaml` (file name kept, default taken): deny rule rendered when `not .Values.ingress.exposeAdmin`. Annotations become `$ann := deepCopy (.Values.ingress.annotations | default dict)`; when deny is rendered and `eq .Values.ingress.className "nginx"` and `nginxCaseInsensitiveAdminDeny`, `set $ann "nginx.ingress.kubernetes.io/use-regex" "true"`. In that case the template `fail`s when any configured `hosts[].paths[].path` contains a regex metacharacter (`.*+?()[]{}|^$\`), because every path is then a regex. `templates/service-admin-blocked.yaml`: guard `and .Values.ingress.enabled (not .Values.ingress.exposeAdmin)`. No `*-snippet` annotation anywhere.
B3. What nginx-ingress does (to be confirmed by AC-15, recorded as not verified if kind is unavailable): with `use-regex` all locations of that host, across all Ingress objects sharing the host, are emitted as case-insensitive regex locations (`~* "^/api/admin"`), longest first, so the deny location wins over `/`. nginx matches locations against the normalized URI: percent-decoded (`%2F` becomes `/`), `.`/`..` resolved, and consecutive slashes merged (`merge_slashes on`, nginx default). So `/API/Admin`, `/api%2Fadmin`, `/api//admin`, `/api/./admin` and `/api/admin/` hit the deny Service (503). Side effects: `^/api/admin` also blocks `/api/administrator` and `/api/admin-x` (no such app routes); other teams' Ingresses on the same host become case-insensitive regex too.
B4. Not covered by the ingress, stated in docs: Traefik and other controllers (Prefix is case-sensitive, `/API/ADMIN` is forwarded; encoded-slash handling is controller- and version-specific, not verified); `merge_slashes off` or operator snippets; hosts not listed in `ingress.hosts`; any path that bypasses this Ingress (LoadBalancer/NodePort Service, port-forward, Gateway API, other Ingress objects). The application authorization is the actual control.
B5. `deploy/scripts/verify-hardening.sh` (lines 160-175): opt-out render uses `--set ingress.exposeAdmin=true`; add an nginx render (`--set ingress.className=nginx`) asserting `use-regex: "true"`, the deny rule and no `snippet`.
B6. Docs: `docs/configuration-guide.md:533` (flag, nginx effect incl. whole-host case-insensitivity, B4 caveats, app authorization as the control; no status wording). `docs/operations-runbook.md` and `deploy/README.md` do not mention the flag (verified); no change. `2026-10-23-plan-issue-281-app-scoped-trusted-documents.md:92` gap note replaced by a pointer to the PRD and this addendum.

### WP-A (PERS-04)
- SEC-P4R-1: Eligibility, `@validTo > valid_to` and the epoch/audit writes happen only when the UPDATE affected exactly 1 row; 0 rows throws `ConsentNotExtendableException` before epoch increment and audit, on all three providers (PG/SqlServer roll back, SQLite writes nothing).
- SEC-P4R-2: The predicate is the authoritative check (it runs in the same locked transaction as the read, so no TOCTOU); no decision may rely on the earlier read or the workflow's `IsRevoked/ValidTo` pre-check. `@now` comes only from the server clock (`DateTimeOffset.UtcNow` or injected `TimeProvider`), never from caller or request input.
- SEC-P4R-3: Text comparison is only valid if all compared values are UTC `"O"`. `CreateConsent` at PG `:487-488` writes `consent.ValidTo.ToString("O")` without `ToUniversalTime()`. Normalize every consent `valid_from/valid_to` write (create, replace, extend) to UTC, or the predicate must be proven offset-safe by test. A consent stored with a non-UTC offset must not be extendable after real expiry and must not be rejected while active.
- SEC-P4R-4: Boundary is `valid_to > @now` (expired at equality). No clock-skew tolerance, rejection wins; document that multi-node skew only shifts the boundary by the skew (accepted, fail-closed direction at the expiry instant).
- SEC-P4R-5: Max duration (default 2): capping in the workflow is accepted because the repository is not an external entry point. The repository must still enforce strictly-later and must never shorten an active consent via extend. Any new REST/GraphQL caller must go through the workflow (architecture test: only `ConsentRecertificationWorkflowService` and `OpenMetadataSyncService` reference `ExtendConsentExpiryAsync`).
- SEC-P4R-6: Exception and sanitizer: fixed message, no id/state/timestamp; `CONSENT_NOT_EXTENDABLE` in `WhitelistedSafeCodes` and fixed-message map; the workflow warning log carries no justification text and no consent values; `ConsentId` only as structured log property.
- SEC-P4R-7: OpenMetadata (default 4): revoke-then-create is accepted only if the revoke is audited (`CONSENT_REVOKED`) and the new consent is created with the same `ConsentRequestId` marker, principal and tenant as `existing`; a failed create leaves the consent revoked (fail-closed) and is logged without values; the race fallback (`CONSENT_NOT_EXTENDABLE`) creates exactly once, never loops, and never creates when the existing consent is revoked by a user (only expired or concurrently extended-out consents are recreated, since sync consents come from `GetActiveConsentsByConsentRequestIdAsync`, a user revoke removes it from the list).
- SEC-P4R-8: No-audit decision accepted; abuse signal is the warning log. Rejected attempts must not increment the table epoch.
- Security tests (`[Trait("Category","Security")]`, all providers via `ConsentQueryContractTestsBase`, plus SQLite unit): `PERS_04_Extend_ExpiredConsent_IsRejected_RowAndRenewalCountUnchanged`, `PERS_04_Extend_RevokedConsent_IsRejected`, `PERS_04_Extend_UnknownId_IsRejected_NoAuditNoEpoch`, `PERS_04_Extend_EqualOrEarlierValidTo_IsRejected`, `PERS_04_Extend_UsesServerTimeInTheUpdatePredicate`, `PERS_04_Extend_NonUtcStoredValidTo_ComparesCorrectly`, `PERS_04_Extend_ExpiryAtExactNow_IsRejected`, `PERS_04_Extend_Rejection_DoesNotBumpEpoch`, `PERS_04_Sync_ExpiredSyncConsent_IsRecreated_NeverExtended`, `PERS_04_Sync_ExtendRejectedByRace_CreatesOnce`, `PERS_04_ExtendRejected_ErrorResponse_ContainsNoConsentValues`.
